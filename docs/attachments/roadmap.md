## 1. 记忆插件本身的后续功能

### 1.1 会话自动总结（让记忆更完整、更自然）

**现状**：`autoSummarize` 已实现但默认关闭——根会话结束（`agent/disposed`）时，用当前模型的 provider/model 汇总本轮对话，解析 JSON 候选、做同一性/价值/闲聊判定，再写入记忆。缺的是：

- 开启策略与默认值（每次结束 / 每日汇总 / 仅在会话达到一定长度时）；
- 质量与噪声控制：重复固化、错误归因、闲聊混入；需要一组可回归的评估语料；
- 成本与延迟：固化调用本身的 token 与失败静默策略；
- 写入体验（原“审核体验”，1.0.0-rc.10 撤销审核后作废）：自动写入的记录直接参与注入；集中展示与来源标注保留价值，批量审核/合并入口已移除；
- 与三端记忆（1.2）配合时的“来源会话/设备”标注。

### 1.2 移动端 / 网页端 / DSH 三端共享记忆

**目标**：同一条记忆在移动端、网页版 DeepSeek、DSH 之间可用且可合并。

- 真源仍是本地 Markdown（可读、可备份、可迁移）；
- 同步层作为可选模块：导出/导入包、远端对象存储、或宿主提供的同步服务；
- 必须解决：身份与授权、端到端加密、离线写入的冲突合并（revision/updatedMs 已有基础）、删除/信任状态的传播；
- 移动端/网页端载体本身不在本仓库内，插件侧先提供稳定的数据格式与同步协议。

**进度（2026-11-09，1.0.0-rc.7 第二刀）**：面板补齐 JSON 包导出/导入与冲突预览——导出带校验和的包；导入先只读预演（新增/更新/相同/冲突），冲突可选“保留本地”或“两边都留”（远端另存为独立版本）。rc.9 补齐拖拽与包体积/记录数提示；仍不做导入历史与自动合并。612/612、隔离 22/22、桌面 rc.6→rc.7 7/7。

**进度（2026-11-09，1.0.0-rc.10）**：撤销用户审核后，冲突预览与 fork 改为“独立版本/直接生效”语义，面板导入对无效 JSON 给出可理解提示；618/618、隔离 22/22、桌面 rc.9→rc.10 7/7，已装桌面待重启（[r197](../progress/2026-11-09_010_撤销用户审核_+_导入_标题收尾.md)）。

**进度（2026-11-09，1.0.0-rc.6 首刀）**：首刀落地“跨端主题字段 + 保留双方冲突”——导出包（`wh-memory-export` v1）与同步变更集（`wh-sync-changeset` v1）携带 `topic` 并写回，旧端缺省为“未归类”；`onConflict: "fork"` 在冲突时保留本地记录，把远端版本另存为 `<name>-shared-<指纹6位>` 独立副本，副本名确定且幂等；API 与 `maintenance-cli` 的 `sync-pull`/`sync-apply` 均可选 `fork`。611/611、隔离 22/22、桌面 rc.5→rc.6 7/7。

### 1.3 跨会话提醒（本文件第 2 节说明机制）

把“需要未来某次会话提醒的事”做成带 due/priority 的记忆/任务类型，由插件在会话开始时注入提醒；完成条件由人确认，或由项目里程碑（如 v1.0 发布）触发。

**进度**：v0.5.0 起任务可投递到宿主调度；v0.6.0 起优先投递到**创建任务的会话**（`notifySessionId`，会话归档自动降级 `new_once`），项目作用域任务的提醒会话带项目 `cwd`（不再“未分组”）。

**登记：提醒落点的“相关性路由”（独立版本，排在 v0.7.0 之后）**。所有者 2026-11-08 提出：新开会话并非全无好处，但应由“任务与本会话的关系”决定，而不是固定策略。

1. 默认仍留本会话；
2. 相关性低（不同项目/主题、无共享关键词）→ 先询问“本会话提醒，还是新开会话？”；
3. 或按关键词判定：命中当前会话主题 → 留本会话；命中其他项目 → 新开会话并带项目 `cwd`；
4. 会话已归档 → 自动降级 `new_once`。

依赖 `src/relatedness.ts`（共享词/同项目/时间邻近/显式链接）与宿主 `target` 可 patch 的能力；**不自动新开会话、不静默改 target**。细节见记忆 `task-session-relatedness-routing`。

**进度（2026-11-09，1.0.0-rc.5）**：首刀落地“关键词路由 + 歧义询问”——`memory_remind` 默认本会话；提醒文字明确命中另一个已知项目时改投该项目 `cwd` 的一次性新会话；同时命中本会话与其他项目、或命中多个项目时**不创建**，返回 `needsConfirmation` 问题，模型询问后用 `route=current`/`route=new` 重试。不自动新开会话、不静默改 target。关闭/重开补投：到点后 30 分钟宽限内重开仍会提示（插件侧 `listDueReminders`；宿主真正投递仍属桌面演练）。

### 1.4 记忆 + 定时任务（v0.5.0 的核心）

**目标**：让记忆不只在“被检索”时出现，还能在合适的时间主动出现。

- **到期提醒**：给一条记忆设置 follow-up（例如“两周后提醒我复查这个决定”），到点由插件/宿主定时任务提醒。
- **到期复习**：对长期未读但重要的记忆做低频提示，避免“存了等于没存”。
- **定时汇总**：每日/每周把新增记录、待处理任务、逾期提醒汇总成一条消息。
- **与宿主能力对接**：优先使用 DSH 的定时任务/提醒接口；宿主没有时退化为面板内的“待办”，不阻塞核心记忆功能。
- **安全边界**：定时任务只读记忆或生成提醒，**不得自动合并或提升信任状态**；写入直接生效、可撤销（1.0.0-rc.10 起无审核步骤）；提醒内容标注“来自记忆”，默认只本地、可关闭。

### 1.5 版本分级（最终发布前实现，先登记）

**目标**：按 token 消耗与功能面提供三档，让所有者按预算选择，而不是所有人都付“全功能”的上下文成本。

| 档位 | token 消耗 | 功能面 |
| --- | --- | --- |
| 低功能版 | 最低 | 核心索引注入 + 五工具最小面；关闭自动固化、批量操作、导入导出等后台能力 |
| 中功能版 | 中等 | 日常可用：低噪声自动固化、自动注入、备份；不启用大规模/多项目增强 |
| 全功能版 | 最高 | 当前开发线的完整能力（自动固化、自动注入、去重、自动备份、迁移引导、多项目/三端） |

**约束**：

- 档位差异用**配置/构建开关**实现，不分叉存储格式；三档必须读同一份 `memory-wh`。
- 档位只影响注入预算、可选功能与后台任务，不改变信任状态与写入语义。
- 交付物：每档的 token 预算建议、功能矩阵、验收矩阵。
- 排期：放在最终发布前（v0.9.0 前后），当前只登记，不排进 v0.2.0。

**进度（2026-11-08，v0.12.0）**：三档已落地为 `edition` 配置（`minimal` / `standard` / `full`，默认 full）。三档共用同一份 `memory-wh`，只影响注入预算建议、可选功能与后台任务；API 对未启用功能返回 `EDITION_DISABLED`，面板隐藏入口并在“存储”面板显示档位。低功能档不注册 `memory_remind`。功能矩阵与 token 预算见 `docs/configuration.md`；验收矩阵仍缺“三档 × 干净环境”的正式演练。 v0.12.1 又补了运行时切换：工具栏“档位”滑条，选择写入 `<记忆根>/settings.json`，即时生效且优先于配置默认值。

### 1.6 项目记忆按主题大类重组（v1.0.0-rc.2 已落地首版）

- 项目 scope 目前只按 cwd/projectKey 隔离，没有主题层级；同一项目下的“考研目标”“考研安排”等只能靠命名与描述区分。
- 所有者澄清（2026-11-06）：项目记忆的主题大类/重组**不单独做**，要与“会话自动总结生成记忆”合并考虑；整个功能到时候再细想，因此先暂缓。见记忆 `project-memory-topics-later`。
- 触发点：做[主题合并](roadmap.md)或会话自动总结时，一并评估“项目内 topic/tag”与“只靠合并 + 索引排序”两种方案。
- **进度（2026-11-09，v1.0.0-rc.2）**：采用“topic 元数据 + 自动合并”的折中方案——每个 scope 一份 `topics.json` 注册表，迁移后所有记录必须有 topic；同主题相关性 ≥80% 自动合并、≥60% 面板确认、跨主题只询问，来源标为被取代、可撤销。旧记录迁移完成（21 条全部归类）。
- **进度（2026-11-09，v1.0.0-rc.4）**：按所有者要求把同主题自动合并门槛从 80 降到 60——同主题 ≥60% 直接自动合并（仍只处理非 disputed/superseded、有主题、非任务/置顶/禁用的记录，可撤销），跨主题仍只在 ≥80% 时进入待确认队列。真实数据中 62 分那组将进入自动合并范围。
- **进度（2026-11-09，v1.0.0-rc.11）**：合并触发条件改为“同主题且相关 ≥60% 自动合并；同主题或相关任一 ≥60% 进面板待确认；两者都不达标不处理”。candidate 也参与扫描；导入/同步的冲突判定不再要求“已审核”，改为“内容不同且本地更新不早于远端”。
- **进度（2026-11-09，v1.0.0-rc.12）**：词面增强——高置信同义词归一到同一词元（考研/研究生考试、发布/release、合并/merge 等），名称里的连字符与下划线按子词再切分；自动合并/待确认列表优先显示中文标题（没有标题才显示记录名）。
- **进度（2026-11-09，v1.0.0-rc.13）**：合并扫描与批量合并跳过已取代/停用记录；批量失败不再中断整批，组列表收起后仍显示“已合并/已跳过”的结果行。
- **进度（2026-11-09，v1.0.0-rc.14）**：合并去掉二次确认，点“确认合并”或“合并这一组”即执行；来源仍可撤销，结果行保留。

### 1.7 相关性系统与人物弧光（P0–P3 已落地；P4 仍评估）

- **想法来源**：记录记忆之间的相关性，后续做三维呈现；在相关性足够高（如 90%）时自动归类合并；基于相关性刻画用户完整人物弧光。
- **可行性结论**：只读评分/可视化/摘要层可行性高；当前“≥90% 自动合并、无需同意”可行性低——词法相似度不等于语义同主题，自动 superseded 会让已验证内容退出注入。
- **规划**：P0 只读相关性索引（共享词、共现、时间、链接、scope/type）→ P1 面板相关记忆/聚类提示 → P2 图谱/三维呈现 → P3 人物弧光摘要（只读视图；首版只做分章时间线）→ P4 可选自动合并（默认关闭、语义评估、可撤销、审计）。
- **自动合并的最低约束（若未来启用）**：语义级评估并在语料上校准阈值；高置信簇 + 默认关闭的显式开关；产物仍是 candidate；来源 `supersededBy` 可一键恢复；写 `merge_apply` 审计（目标/来源/阈值/评估版本）；面板可见可撤销、失败可回滚。
- **登记记忆**：`relatedness-system-plan`、`auto-merge-policy`。
- **进度（2026-11-09，v1.0.0-rc.3）**：P3 首版落地为**只读分章时间线**——`arc.view` 跨 `_user` 与全部项目 scope，按主题注册表成章、章内按时间排序，标出来源/信任状态/取代链；不返回正文、不调模型、不写记忆。面板“人物弧光”与关系图并列，仅全功能档可见。P0/P1/P2 已分别由 v0.7.0 的相关记忆与 v0.10.0 的关系图落地；P4 自动合并按 1.6 的“同主题且相关 ≥60 自动、只满足一项进待确认”推进（rc.11 起）。
### 1.8 记忆质量与检索优化（v0.6.0 的核心）

- **问题**：当前记忆能跨会话注入，但“写什么、写得准不准、检索命中率、索引预算、写入负担”没有度量；会话压缩后仍可能丢决策。
- **优化方向**（对应 v0.6.0）：
  1. 规则分层：硬规则进 `AGENTS.md`；偏好/决策进 verified 记忆；一次性任务进阶段报告；避免把临时信息写进长期记忆。
  2. 写入口径：一条记录只表达一个决策，正文写“结论 + 原因 + 边界”；名称可检索；描述保持精炼（只有 description 进索引）。
  3. 会话自动总结策略：开启 `autoSummarize` 的质量门槛、写入节奏、去重与“不值得记”的判定。
  4. 检索与召回：新会话先 `memory_search`/`memory_list` 的默认动作；相关记忆提示；召回排序的可解释性。
  5. 去重与主题合并：近重复检测 → 主题合并建议，减少碎片与索引预算占用。
  6. 索引预算治理：索引字节占用、pinned/importance 的排序影响、超预算时的降级提示。
  7. 度量与复盘：写入命中率、重复率、召回命中、索引占用、压缩后决策丢失率（抽样）。
- **为什么单独一个版本**：这是记忆插件的核心能力，与提醒（v0.5.0）、界面（v0.8.0）、发布（v0.9.0）解耦；单独成版便于用指标验收，也避免混进其他功能后无法归因。
- **退出条件**：上述指标有基线并能用真实一周使用对比；注入噪声不显著上升；索引不超预算；至少 3 个“压缩后仍被记住”的正例与 3 个“不该写却没写”的反例被文档化。
- **验证**：合成语料 + 真实一周使用记录 + 面板指标截图。

## 2. 跨会话提醒：现在的可行路径

Agent 的会话本身是无状态的；要在未来会话里“记得”，必须依赖会话之外的持久物：

| 机制 | 现在是否可用 | 说明 |
| --- | --- | --- |
| 记忆索引注入 | 可用（本插件） | 记录直接进入 system prompt（1.0.0-rc.10 起无审核）；适合“长期事实/偏好/待办” |
| 项目文件 | 可用 | 如本文件、`AGENTS.md`、`current-status.md`；未来会话按项目上下文读取 |
| 定时任务 | 可用（宿主 `schedule_create`） | 到点向指定会话投递提醒；依赖 DSH 在运行 |
| 外部日历/提醒 | 不在本仓库 | 需要额外集成 |

**结论**：不读文件、不读记忆、也没有定时任务时，agent 无法跨会话记得；插件解决的正是“记忆注入”这一层，定时任务解决“到点提醒”这一层。建议两者配合：完成条件写进记忆/大纲，时间点交给定时任务。

## 5. 版本路线：v0.2.0 → v1.0.0

### 5.0 版本与兼容原则

- 语义化版本：`0.x` 允许数据格式与 API 演进，**每次改动都必须带可逆迁移**；进入 `1.0` 后数据格式与工具参数冻结，破坏性变更只进大版本。
- 每个版本都必须：更新 `CHANGELOG.md`、写 `docs/progress/` 阶段报告、给 `docs/progress/2026-11-09_018_持久记忆_WH（dsh-auto-memory-wh）阶段总结报告.md` 与验收清单留证据；候选包必须在隔离 profile 上跑 21 步验收入口。
- 公开发布（G5）只在 **v1.0.0 或明确决定发布时**执行；此前所有版本都按“本地自用候选”管理。
- **对 DSH 更新的韧性**（所有者 2026-11-06 确认）：非破坏性更新插件不掉；破坏性更新记忆不损坏，允许入口短暂消失但必须可恢复。实现：`engines.dsh` 覆盖已知兼容区间 + 精确版本豁免（`dsh plugin allow-version` / 插件管理器）+ 升级前后宿主兼容探针；恢复过程不迁移、不删除记忆。
