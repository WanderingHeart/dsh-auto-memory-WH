## 起因与范围

[r99](2026-11-05_044_rc.11_断电演练工具与_VirtualBox_步骤.md) 只完成了“进程被杀”的干跑，不能代表掉电。按 [手动隔离测试](2026-11-05_002_需要你亲自参与的隔离测试（rc.11_候选）.md) 测试 B，所有者在 VirtualBox 中新建 Windows 客户机，安装候选包所需的 Node 运行时，把项目复制进客户机后执行真实断电。

范围仅限：合成根目录、单个客户机、单次掉电、存储层恢复；不包含真实用户数据、真实硬件坏盘、文件系统损坏或桌面 UI。

## 观察与限制

- **掉电未留下半截事务**：断电窗口落在两次原子写之间，恢复报告 `none`，没有 journal、`.tmp` 或锁。这说明“已提交即完整”在真实掉电下成立，但**本次没有实际触发半截事务回滚**；回滚路径由 [r54](2026-11-04_031_rc.8_子进程退出恢复矩阵.md) 的三点进程退出、[r91](2026-11-05_036_rc.11_离线升级失败演练：截断包与卸载_重装后的记忆保持.md) 的失败安装与 r99 干跑覆盖。
- **环境兼容性发现**：客户机断电重启后，Windows 校正时钟会使 Node 的 libuv 在异步文件操作中触发 `Assertion failed: new_time >= loop->time, file src\win\core.c, line 327`（Node 26.13 与 Node 24.22 均可复现）。这是虚拟机时钟跳变下的运行时断言，不是数据损坏。校验脚本已改为**全同步路径**（`scanSync`，不进入事件循环）以绕过该问题，并保留了说明注释；写入工具本身未受影响。
- 仅一次、单客户机、Windows 10、合成数据；未覆盖真实坏盘、掉电时的文件系统元数据损坏、多磁盘/网络存储，也未覆盖桌面 UI 草稿。
- “锁不自动回收”的设计未在本次触发（未遗留锁），但 r99 干跑已验证“遗留锁 → 运维解锁 → 恢复”的路径。
