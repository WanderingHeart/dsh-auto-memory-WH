# S05 rc.8 隔离桌面离线缓存修复（r60）

> 时间：2026-11-04（Asia/Shanghai）。状态：首次离线安装被缓存门槛阻断；修复准备完成，安装与卸载仍待复验。v0.1.0 工作量估算约 **75%**，不是测试通过率。

## 本轮发生了什么

用户允许仅在 `.work/S05/native-real-user-home/profiles/desktop` 的隔离桌面 profile 安装、验证并卸载本地 `dsh-auto-memory-wh@0.1.0-rc.8`。以正常 Windows 用户运行 `Check` 返回 `ready-for-isolated-desktop-install`：四个基础配置与备份一致，WH 未安装，无 DSH 进程；本地包 SHA-256 为 `4FECDC25AA7C0295A164DD6EC9E1D2D599453F9A3AB996E90B1437FAB1F4954B`。

用户在断网条件下执行一次 `Install`。官方内置 CLI 的 pnpm 子进程报 `ERR_PNPM_NO_OFFLINE_META`：桌面专用缓存缺少 `@deepseek-ai/schemastery@>=3.18.2 <4.0.0-0` 的离线元数据，进度为 resolved 0、downloaded 0、added 0，插件命令退出 1。诊断目录为隔离 profile 下的 `.plugin-manager/logs/operation-5jS8da/`。**未运行卸载，也未重试安装。**

失败后逐项核对：`package.json`、`cordis.patch.yml`、`cordis.yml`、`pnpm-workspace.yaml` 的 SHA-256 与 r59 空白备份完全一致；无 `pnpm-lock.yaml`、无 `node_modules`，WH 未进入依赖或 bundle。已有的 `.plugin-manager` 失败日志保留。日常 DSH、真实记忆与模型密钥未参与。

## 修复与核对

隔离 CLI 测试 profile 的项目内缓存已有同一 pnpm v12、同一 npm registry 的四个依赖元数据文件。将 `yaml`、`@deepseek-ai/cosmokit`、`@deepseek-ai/schemastery`、`@standard-schema/spec` 的元数据逐文件复制到**桌面专用** `.work/S05/native-desktop-cache/pnpm/v12/metadata/`，逐文件复核 SHA-256 一致；没有联网安装或修改宿主目录。操作脚本现于 `Check` 和 `Install` 入口验证这四个文件的固定哈希，避免再次在断网后才发现元数据缺失。PowerShell 语法检查无错误；正常用户下重新运行只读 `Check` 通过，仍显示空白基线、WH 未安装、DSH 进程数 0。

## 下一步及限制

用户再次手动断网、保持 DSH 关闭后，运行相同的受限 `Install` 命令。只在输出确认 `installed-in-isolated-desktop-profile` 后运行 `Remove`；任一步失败就保留现场并停止。四个元数据文件齐全不等于离线安装已成功，pnpm 还须实际验证 store 内容、包解析与卸载路径。通过安装/卸载也只证明包管理层，不代表 WH 原生页面、登录、注入或审计已通过。
