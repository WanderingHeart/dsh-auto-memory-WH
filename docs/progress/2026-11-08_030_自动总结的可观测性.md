# v0.12.2 — 自动总结的可观测性

- 日期：2026-11-08
- 阶段：S05 · v0.12.2
- 类型：功能可见性 + 审计口径（不改默认行为）
- 证据：`docs/evidence/S05-0.12.2/`、`docs/evidence/S05-0.12.2-acceptance/summary.json`、`docs/evidence/S05-real-data-migration/desktop-upgrade-0.12.2.json`

## 1. 为什么做

自动总结（autoSummarize）在 v0.6.0 起就存在，默认关闭，需要所有者显式配置 provider/model 才会运行。但开启后，面板只能看到“候选/待审”的最终结果，看不到：

- 本次宿主启动后到底跑过几次；
- 最近一次是写入、跳过、被截断、解析失败还是模型失败；
- 累计写入与跳过各多少。

没有这些数字，所有者无法判断“开着自动总结到底有没有用”，也无法区分“没有新内容可固化”和“配错了模型导致每次都失败”。本轮把运行摘要做进面板，只记录数量与结果，不保存对话内容，也不改变默认行为。

## 2. 实现

### 2.1 运行摘要

新增 `src/consolidation-stats.ts`：

- `ConsolidationOutcome`：`written | nothing-written | skipped | truncated | parse-error | llm-error | failed`。
- `ConsolidationRun`：`{ at, outcome, reason?, created, updated, superseded, skipped }`。
- `ConsolidationSnapshot`：`{ enabled, runs, lastAt?, lastOutcome?, lastReason?, lastCreated, lastUpdated, lastSkipped, totals: { written, skipped } }`。
- `ConsolidationStats.record(run)` 保留最近 50 次运行；`snapshot(enabled)` 返回累计值与最近一次。`totals` 用独立计数器累计，不受环裁剪影响。

### 2.2 埋点

`src/consolidate.ts` 在 `registerConsolidation` 内创建 `ConsolidationStats`，并在每条退出路径记录结果：

- 未达门槛 → `skipped` + 具体原因；
- 模型错误 → `llm-error`；`max-tokens` → `truncated`；候选解析失败 → `parse-error`；
- 写入完成 → `written` 或 `nothing-written`，同时记录 created / updated / superseded / skipped。

`stats: () => snapshot` 加入 `ConsolidationHandle`，`src/index.ts` 把它挂到 `groups.list` 的 `consolidation` 字段。`src/client/ManagementPage.tsx` 在“存储”抽屉的“功能档”下方显示：

- 未开启：`自动总结：未开启（config autoSummarize）`；
- 开启但本进程还没跑过：`已开启，本次宿主启动后尚未运行`；
- 开启且跑过：`最近一次 <本地时间>：写入 N 条候选，跳过 M 条（累计写入 K）`。

### 3.1 许可清单格式修复

首次打包后验收在 `license` 步失败。原因是 `THIRD_PARTY_NOTICES.md` 重生成时用了自定义列：

- lock 行是四列并带 `(optional)/(peer)` 后缀，而 `runtime-license-audit.mjs` 只认精确的 `| node_modules/<path> | <version> | <license> |`，并要求 version/license 与 `package-lock.json` 的 `packages[path]` 逐条一致；
- 运行时依赖写成了列表项，而审计要求 `| <name> | <version> | <license> | \`<LICENSE sha256>\` |` 四列行（cosmokit 1.8.6、schemastery 3.18.5、`@standard-schema/spec` 1.1.0、yaml 2.9.1）。

修复后按上述两种精确格式重生成（`.work/notices-182.mjs`：lock 只用 lock 自带 version/license，三列；运行时四列并附 SHA），重新打包、重装 `wh-s05`、重跑 22 步即全过；候选包哈希由 `036b450f…3d910` 变为 `cdcf5fd8…ed95`，桌面脚本同步更新。

## 4. 边界

- 只统计数量，不含任何对话或候选正文；面板不展示跳过原因明细（原因已在运行记录的 `reason` 里，后续可按需展开）。
- 运行摘要是**进程内**的：宿主重启后归零；需要跨重启的历史，应走审计日志而不是这里。
- 不改变 autoSummarize 的默认值与触发频率，也不改变审核门。
