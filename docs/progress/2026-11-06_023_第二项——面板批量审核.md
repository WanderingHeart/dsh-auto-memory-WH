# r120：v0.2.0 第二项——面板批量审核

- 日期：2026-11-06
- 范围：`src/client/ManagementPage.tsx`、`tests/management-page.spec.tsx`（客户端与管理测试）
- 状态：本地开发线完成，未构建、未打包、未发布

## 起因

日常使用时，审核是逐条进行的：打开、阅读、勾选、保存。积压十几条候选时，操作成本主要花在重复点击上，而不是阅读本身。本项只减少重复操作，不改变“人必须阅读并确认”的语义。

## 实现

- 列表每条记录增加复选框（`aria-label="选择 <name>"`）。
- 勾选后出现批量条：`已选 N 条`、`批量通过审核`、`批量退回待审核`、`取消选择`。
- 批量动作：
  1. 只处理当前选中且状态不等于目标状态的行（已 verified 的不会重复审核）；
  2. 每条都用该行当前的 `revision` 调既有 `memory.review`，不新增服务端接口；
  3. 执行前弹出确认框（“请确认你已阅读这些内容”），取消则不发请求；
  4. 部分失败时列出失败名称，成功的条目不会回滚；
  5. 完成后清空选择并刷新列表。
- 切换范围、会话、筛选、分页时自动清空选择，避免把 A 页的选择带到 B 页。

## 验证

## 边界

- 仍是逐条 revision、逐条请求；没有引入“按筛选条件全量审核”的捷径，避免误审。
- 只影响面板客户端；服务端审核路径、信任规则、注入逻辑未改。
- 0.1.0 冻结候选与 `lib/` 未重建；v0.2.0 候选包尚未切出。
- 面板深色主题、完整键盘操作与无障碍仍属未验收边界。
