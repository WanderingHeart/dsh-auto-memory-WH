# r124 — v0.3.0 第一步：项目 scope 只读盘点

- 时间：2026-11-06 23:53（Asia/Shanghai）
- 阶段：S05 / v0.3.0 开发线
- 状态：只读盘点与 CLI 入口完成；移动/合并/归档/主题合并尚未开始
- 关联：`docs/attachments/roadmap.md` 5.2 第 1 项

## 1. 目标

v0.3.0 的第一项是“项目 scope 的创建/移动/合并/归档”。第一步只做**只读盘点**：列出 `memory-wh/` 下现有的项目 scope、它们的 cwd、记录数与最近修改时间，不引入任何写操作。

## 2. 实现

- 新增 `src/projects.ts`：
  - `listProjects(root)` 返回 `{root, projects, skipped}`；
  - 只扫描根目录下的目录；跳过 `_user`、`.backups`、`node_modules`；
  - 目录必须含合法的 `.wh-project.json`（`version === 1` 且 `cwd` 为非空字符串），否则不是项目 scope（缺失标记静默跳过；损坏标记进 `skipped` 并带原因）；
  - 记录数只数 `.md`（排除 `MEMORY.md`），不读取正文；
  - 结果按最近修改时间倒序，其次按目录名排序。
- `src/maintenance-cli.ts` 新增 `projects` 命令（请求体只需 `{ "root": "..." }`），并更新 `--help` 文案。

## 3. 验证

- 新增 `tests/projects.spec.ts`（2 项）：
  - 两个项目目录 + 非项目目录 + 损坏标记：返回 2 个项目、记录数分别为 2/1、`broken` 进入 `skipped`、`not-a-project` 不被列出；
  - 根目录不存在时返回空盘点。
- `typecheck` 通过；目标测试 2/2 通过。

## 4. 边界

- 纯只读，不创建、不改写、不移动任何项目目录；
- 尚未提供面板入口（下一步再决定放维护 CLI 还是面板只读视图）；
- 尚未处理 `projectKey` 冲突/重映射、跨机迁移、合并与归档；
- `skipped` 只带目录名与原因，不含 cwd 或正文。

## 5. 下一步

1. 项目 scope 重映射/移动（改名、换机）与冲突检测；
2. 主题合并（只读聚类建议 → 勾选 → 预览 → candidate → 来源 `supersededBy`）；
3. 归档与“项目错配”故障注入。
