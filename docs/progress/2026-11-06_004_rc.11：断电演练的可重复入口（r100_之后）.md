# S05 rc.11：断电演练的可重复入口（r100 之后）

- 日期：2026-11-06
- 状态：隔离、合成数据；产品代码未改；入口脚本已干跑
- 关联：`docs/progress/2026-11-05_002_需要你亲自参与的隔离测试（rc.11_候选）.md` 测试 B；`scripts/verification/manual/power-loss.ps1`、`power-loss-verify.mjs`
- 证据：干跑输出 `.work/S05/powerloss-wrapper-dryrun/verify-killed-process.json`（15/15）；参考真实断电运行 `docs/evidence/S05-rc11-manual-power-loss/verify.json`（r100）

## 起因

r100 已用 VirtualBox + Windows 10 客户机完成一次真实强制断电，但那次是人工分步执行：装 Node、复制项目、起写入、宿主机断电、重启后跑校验。用户下一步要求“把断电演练做成可重复入口”，即所有者不需要每次重新理解命令顺序，也不能让重复演练覆盖 r100 的参考证据。

## 入口设计

新增 `scripts/verification/manual/power-loss.ps1`（ASCII、PS 5.1 可执行）：

| 动作 | 行为 |
|------|------|
| `-Action Prepare -Root <目录>` | 校验根目录是测试路径（叶子必须为 `powerloss` 或 `powerloss-rerun`，且不在仓库内），设置写入间隔后调用 `power-loss-write.mjs`，持续写 5 条基线 + 序号直到断电。 |
| `-Action Verify -Root <目录>` | 调用 `power-loss-verify.mjs`：先按维护解锁流程释放断电遗留锁，再恢复 journal，最后逐项核对（15 项）。证据写到 `<根目录>\evidence\verify-<时间>.json`。 |
| `-Action Status -Root <目录>` | 打印 `progress.json` 与当前遗留锁，便于断电前确认写入进度。 |

配套修改：

- `power-loss-verify.mjs` 支持 `POWER_LOSS_EVIDENCE` 环境变量；未设置时仍写仓库默认路径（`docs/evidence/S05-rc11-manual-power-loss/verify.json`），设置时写指定文件。这样重复演练写自己的 `evidence\`，不会覆盖 r100 的参考证据。
- 目标内存根不存在时，校验器输出明确提示（“run the Prepare step first”）而不是抛 `ENOENT` 堆栈。
- `docs/progress/2026-11-05_002_需要你亲自参与的隔离测试（rc.11_候选）.md` 的 B2/B4 改为单条入口命令，并保留底层 `node` 命令作为等价说明；`scripts/verification/README.md` 增加入口一行。

## 干跑

在本机用“启动写入 5 秒后结束进程”代替断电（验证入口管道与证据路径，不冒充断电）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verification\manual\power-loss.ps1 -Action Prepare -Root <临时根>
# 5 秒后结束写入进程
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verification\manual\power-loss.ps1 -Action Verify -Root <临时根>
```

结果 15/15 PASS：释放 2 个遗留锁（`.wh-writer.lock`、`_user/MEMORY.md.lock`）、journal `rolled-back`、32 条记录、基线逐字节不变、序号 27/27、索引 2372 字节；证据落在 `<临时根>\evidence\verify-20261106-112903.json`，仓库参考证据哈希保持 `47765356…8585fd` 未被改写。

另验证：`-Action Status` 在空根上输出“no progress.json yet / no lock files”；`-Action Verify` 在不存在的内存根上以非零退出并给出可读提示。

## 边界

- 干跑用的是“结束进程”，不是真正的掉电；掉电结论仍以 r100 的真实运行与 r99/r91 的恢复演练为准。
- 入口只适用于隔离虚拟机内的合成根；脚本拒绝仓库内路径，避免误指真实记忆目录。
- 未自动执行断电，也没有做“断电瞬间恰好落在 journal 写入中”的时序控制；这类故障注入仍由 r54/r99 的确定性场景覆盖。
