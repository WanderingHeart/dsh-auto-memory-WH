# v0.7.0 规划：提醒可达性 + 相关性只读

> 状态：**已实施（2026-11-08，v0.7.0）**。M1 `tasks.due` + 小鲸鱼轮询、M2 `src/relatedness.ts` + API、M3 面板相关区均已完成；47 个测试文件 / 494 用例通过；已切版（候选 161,477 字节 / `12EC4B0F…B4F09E`）、隔离 `wh-s05` 21/21（[r156](2026-11-08_005_候选包构建与隔离_21_步验收.md)），日常桌面已升级、待重启（[r157](2026-11-08_006_日常桌面升级到_v0.7.0.md)）。
> 版本定位：v0.6.0（质量与检索）之后的“让提醒更醒目、让记忆之间能互相看见”，不改变信任与审核语义。

## 1. 目标

1. **提醒可达性**：DSH 打开、但用户正在别的会话时，到期任务除“宿主投递新会话”外，再用小鲸鱼气泡提醒一次；没装小鲸鱼时静默降级，不报错、不打扰。
2. **相关性只读**：给每条记忆算出“相关记忆”（共享词、同项目、时间邻近、显式链接），在面板里列出并说明理由；**不合并、不自动 supersede、不落盘**。这套分数同时是后续**自动合并（P4，仅产候选、人工确认）**与**三维/图谱呈现（P2）**的共用底座，所以本版就把它做成稳定、可解释的纯函数并保留 top-N 理由，避免以后重写。

## 2. 明确不做

- 不自动合并/自动归类（P4 才评估，需单独授权）。
- 不做图谱、三维点云呈现（P2，排 v0.8.0）。
- 不做人物弧光摘要（P3）。
- 不修改小鲸鱼仓库的现有行为；只依赖可选钩子。
- 不让提醒绕过审核门：只有 `verified + open` 的任务才会提醒（与 v0.5 一致）。

## 3. 子能力 A：小鲸鱼提醒适配器

### 3.1 依赖的钩子

上游补丁已就绪（本地分支 `.work/whale-upstream`，`feat/external-notify-hook`，commit `1789643` + `c408e09`）：

```js
window.__dshWhaleNotify({ text?: string, lines?: BubbleLine[], ttlMs?: number, sound?: boolean }) => boolean
```

- 返回 `true` 表示已入队；`false` 或函数不存在表示不可用。
- `ttlMs: 0` 表示常驻；`sound: true` 走“任务结束音”的设置与播放路径。
- 它尊重小鲸鱼自己的气泡总开关；我们不直接操作 DOM。

### 3.2 适配器行为

```
每 30s + 页面可见性变化时：
  due = GET tasks.due（只读，返回 taskStatus=open 且 remindAt <= now 的 verified 任务）
  对每条 due：
    sig = name@remindAt
    if sessionStorage 已记录 sig：跳过
    调用 window.__dshWhaleNotify({ lines:[…], ttlMs: 0, sound: true })
    成功则记录 sig（保留 24h，清理过期项）
失败/无钩子：什么都不做（已有 memory_tasks 注入与宿主投递兜底）
```

- **单次触发**：只在到达提醒时间后弹一次；不再做“提前 5 分钟 / 到点 / 到点后 30 分钟”三个时点。
- **常驻气泡**：`ttlMs: 0`（小鲸鱼 `sceneOpen` 的 0 = 不布自动关闭计时器），气泡留在屏幕上，直到用户点掉或下一次提醒替换。
- **提醒音**：`sound: true` 复用挂件自带的“任务结束音”设置与播放路径（`playTaskEndSound()`；`soundOn` 与 `taskEnd.on` 都开才响），不引入新音频文件。
- **配置**：`notify.whale: 'auto' | 'off'`，默认 `auto`（检测到钩子才启用）。面板先给只读状态；开关放 v0.8.0 的 UI 打磨。
- **降级**：`typeof window.__dshWhaleNotify !== 'function'` → 适配器不注册任何定时器（零成本）。
- **版本漂移**：小鲸鱼升级会覆盖 `assets/whale-widget.js`。提供 `scripts/verification/reapply-whale-patch.mjs`（检测钩子、缺失时从 `.work/whale-patch/whale-widget.patch.js` 重新注入并校验），并在 r 报告里记录版本。

### 3.3 新接口

`tasks.due`（只读，POST，scope/cwd）：

```json
{ "items": [{ "name": "eat-now-reminder", "title": "去吃饭", "dueAt": 1794050761581, "remindAt": 1794050761581, "taskStatus": "open" }], "now": 1794050700000 }
```

- 复用 `store.list`，过滤 `type='task' && status='verified' && !disabled && taskStatus='open'`，按 `remindAt ?? dueAt` 排序，最多 20 条。
- 不返回 body，避免把正文发到渲染层。

## 4. 子能力 B：相关性只读（P0/P1，自动合并与三维的底座）

> 定位：本版只读展示；但打分与“关系边”结构按未来 P4 自动合并、P2 三维/图谱的需要设计——P4 只消费 `score + reasons` 产出候选（仍需人工确认），P2 只消费关系边，不重新推导分数。

### 4.1 打分（`src/relatedness.ts`，纯函数）

输入两条记录 + 上下文，输出 0–100 分与理由：

| 信号 | 权重 |
| --- | --- |
| 正文里的显式链接 `[x](y.md)` 或 `name` 提及 | 40 |
| `supersedes`/`supersededBy` 关系 | 40 |
| 标题共享 token | 最高 25 |
| 描述共享 token | 最高 15 |
| 正文共享 token（tf 限制） | 最高 15 |
| 同项目 cwd | 10 |
| 同 type / 同 scope | 各 5 |
| 更新时间相差 ≤ 7 天 | 5 |

- token 化：ASCII 单词小写 + 去停用词；中文用 2-gram，避免分词依赖。
- 取 top-5 理由（“共享：导航、激光雷达”“同项目 dsh-auto-memory-WH”“正文链接到 x”）。
- 阈值：< 30 不展示；30–59 标“弱相关”；≥ 60 标“强相关”。
- 纯计算、不缓存、不写文件；500 条以内用倒排索引，目标 < 200ms。

### 4.2 接口与面板

- `relatedness.forRecord`（POST，name/scope/cwd，limit=5）→ `{ items:[{name,title,score,strength,reasons[]}], scanned }`。
- P1 面板：记录卡片展开后加“相关记忆”区，点名字跳转；没有相关记录时显示“暂无相关记忆”。
- 不加列表徽标：相关数不作为列表列，只在展开区展示（避免列表变重、也避免“相关=重要”的误导）。
- 可选（P1 末尾）：质量体检加第 9 类提示 `isolated-record`（既无相关、也无被引用、正文 < 200 字），帮助发现“孤岛记忆”。

## 6. 测试矩阵（最小但覆盖全部分支）

- 适配器：钩子存在/不存在/抛错；sessionStorage 已通知/未通知；窗口内/窗口外；多次轮询；`notify.whale='off'`。
- `tasks.due`：候选/已完成/已取消/未审核不返回；user+project 合并；上限 20。
- 相关性：显式链接 > 同项目 > 共享词；无关记录 score < 30；中英混排；空正文/仅标题；500 条 < 200ms。
- 面板：相关区渲染、点击跳转、空态、断网重试不崩。
- 回归：全量 vitest + typecheck + build + 21 步。

## 7. 风险

1. **上游不合并**：钩子是本地补丁；小鲸鱼升级会覆盖。用重打脚本 + 报告记录版本兜底；适配器始终可选。
2. **渲染层节流**：窗口在后台时定时器可能被降频，气泡可能晚到；宿主投递仍然兜底。
3. **中文 2-gram 误报**：用阈值 + 理由透明 + 只读，不触发任何写操作；先按单点样本校准。
4. **面板性能**：相关性按需计算（打开记录时），不做全量预计算。

## 8. 已拍板

1. 气泡时点：**只在到达提醒时间后弹一次**；气泡常驻（`ttlMs: 0`），并在同一时刻播放小鲸鱼自带的“任务结束音”（`sound: true`）。（2026-11-08 更新，取代原“提前 5 分钟 / 到点 / 到点后 30 分钟”三时点方案）
2. 相关性：**只在记录展开区**展示，不加列表徽标。
3. `notify.whale` 默认 **auto**（检测到钩子才提醒）；关掉后仍有宿主投递与会话内注入兜底。
4. 提醒落点：默认投递到**创建任务的会话**（`notifySessionId`，v0.6.0 已有）；后续版本再加“任务与本会话关系判断 + 询问/关键词决定是否新开会话”，先登记为独立版本（见 roadmap 1.3 与 `docs/attachments/roadmap.md`）。
