# S05 rc.1 异步组装规模与事件边界（r14）

日期：2026-11-03。状态：**partial**。本报告对应 rc.1 之后的工作树；上一轮安装的 rc.1 包不包含本轮取消信号修正，未重新打包、安装或发布。

## 改动与发现

使用 0、1、6、100、2000 条既有合成记录，通过实际 Cordis、SystemPrompt 和 WH 插件的 `assemble()` 路径测量异步扫描、段落替换及审计入队。每组顺序运行五次，片段预算 4096 UTF-8 字节。完整原始数据见 [组装基准](../attachments/public-validation.md)。

| 记录数 | 首次 ms | 五次中位数 ms | 最大 ms | 输出字节 |
|---:|---:|---:|---:|---:|
| 0 | 8.45 | 6.24 | 8.45 | 0 |
| 1 | 10.74 | 6.50 | 10.74 | 549 |
| 6 | 15.73 | 9.09 | 15.73 | 1234 |
| 100 | 64.08 | 62.09 | 64.08 | 4043 |
| 2000 | 945.67 | **891.82** | 945.67 | 4043 |

先前 rc.0 的同步路径基准在 2000 条约 1552.92 ms；本轮量到更低的数值，但两个脚本的测量边界和文件缓存状态不同，不能将差值当作严格 A/B 提速率。接近 0.9 秒的中位数仍不宜称为低延迟。审计刷盘不计入上述组装等待时间，模型、HTTP、浏览器、压缩和子代理均不在测量链路内。

宿主 `AssembleContext` 可带 `AbortSignal`。WH 现在在扫描前及扫描完成后检查取消状态；已取消的组装输出空记忆段，并将 `assembly-aborted`、0 字节写入逐次组装审计。最终段落替换前也再次检查信号，缩小取消后仍暴露内容的窗口。当前底层文件读取不会在取消时立刻停止，所以此修改保证失败关闭，**不保证节省已经启动的 I/O**。

新增真实 Cordis/SystemPrompt 集成用例，覆盖两个项目同时组装且同名项目记录不串值、用户范围共同可见、其他 waterfall 监听器保留结果、无 agent 时为空、开始前取消与扫描中取消，以及宿主 `complete` section 最终独占系统提示词。`complete` 的最终覆盖发生在 waterfall 之后，因此 WH 仍可能记录一次非零字节的 *render_attempt*；这只代表组装尝试，不能解释为模型实际收到记忆。此行为与页面审计文案一致，后续需继续评估是否可以由宿主提供最终呈现确认。
