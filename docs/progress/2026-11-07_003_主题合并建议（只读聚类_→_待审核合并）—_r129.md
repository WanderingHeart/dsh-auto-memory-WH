# S05 v0.3.0 主题合并建议（只读聚类 → 待审核合并）— r129

- 时间：2026-11-07
- 范围：v0.3.0 / 5.2 第 3 项“冲突与取代”的后半（主题合并建议）
- 状态：实现与测试完成；未构建 lib、未打包、未切版本

## 1. 背景

r128 支持手动标记“B 取代 A”，但用户仍要自己发现“哪些记录在讲同一件事”。近重复只比较整段文本，抓不到“标题不同、共享关键词”的主题簇。本步增加**只读**主题聚类建议：只给候选与预览，最终由人确认；合并产物是 candidate，来源标 `supersededBy`，不删除、不自动合并、不静默改写。

## 2. 实现

### 2.1 聚类 `src/merge.ts`

- `suggestMergeClusters(records, {minShared=2, maxClusters=20, maxRecords=500, maxTokensPerRecord=16})`：
  - 过滤已取代/静音；每条形如 `title + description + body` 取显著 token（复用 `duplicates.tokenize`，去停用词/纯数字/长度 <2，上限 16）；
  - 只有出现在 2 条以上、且不超过 60%（小集合允许到总数-1）的 token 才算“有信息量”；
  - 先统计**成对**共享的显著 token 数，只有达到 `minShared` 的配对才并查集合并，避免弱链把全库连成一团；
  - 每组要求所有成员共享至少 `minShared` 个 token；建议名取共享度最高 token 的 slug + `-merged`，建议类型取组内多数类型；按 score 排序并限流。
- `buildMergedBody(members)`：固定 `## 来自 <name>` 分节、保留顺序；`mergedDescription` 生成“合并自 N 条（名单）。…”并截 500 字符（含 `memory_write` 的 description 上限）。

### 2.2 API `src/management-api.ts`

- `memory.mergeSuggest`（POST，`minShared` 1–6）：只读，返回 `{scanned, minShared, clusters}`，成员不含正文；
- `memory.merge`（POST，`name/type/members/confirm`）：
  - 必须 `confirm:true`；2–20 个成员；成员 revision 必须与当前一致；已取代/不存在/名称与目标相同都会拒绝；
  - 目标写入为 **candidate**（正文按来源分节），随后逐条 `store.supersede(..., targetName)`；来源保留正文、只标 `supersededBy`；
  - 有 `sessionId + cwd` 时写审计事件 `kind: 'merge_apply'`（`target/sources` 字段，`AuditEntry` 类型已扩展）。

### 2.3 面板 `src/client/ManagementPage.tsx`

- 工具栏“合并建议” → 主题簇卡片（共享词、成员状态）；
- “预览合并”：逐个 `memory.read` 在本地拼出分节正文，显示在 `<pre>`；
- 可勾选成员、改目标名称/类型；“确认合并”二次确认后 POST `memory.merge`，刷新列表；范围/会话切换时清空。

## 3. 语义与边界

| 项 | 行为 |
| --- | --- |
| 自动性 | 无自动合并、无模型改写；必须人工勾选并确认 |
| 产物 | 新目标记录 status=candidate，需照常审核后才注入 |
| 来源 | 保留原文件与正文，status=superseded + supersededBy=目标；可恢复 |
| 范围 | 仅同一 scope；不跨项目/用户 |
| 审计 | `merge_apply` 事件记录 target 与 sources（含 sessionId/cwd 时） |
| 预览 | 本地按 `## 来自 <name>` 拼接，不落盘；确认时才写 |
