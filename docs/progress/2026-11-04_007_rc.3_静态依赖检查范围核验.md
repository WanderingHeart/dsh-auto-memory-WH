# S05 rc.3 静态依赖检查范围核验（r30）

日期：2026-11-04。状态：**partial**。本轮只读取本机桌面版 DSH `0.2.1-rc.5` 的打包代码，定位 `plugin peers check` 的实际执行路径；没有运行安装、修改插件或接触记忆。

## 发现

打包的桌面 CLI 将 `dsh plugin --profile wh-s05 peers check` 中的插件参数转交给普通 DSH CLI；普通 CLI 明示把剩余参数原样交给 pnpm。插件命令解析出所选 profile 目录，插件管理器以该目录为 `cwd` 启动 pnpm。因此此命令检查的是 **profile 自身的 pnpm 依赖树**。它没有把 `app.asar` 内的宿主包目录并入这棵树。

[只读检查结果](../attachments/public-validation.md)保存了相关打包文件的 SHA-256、行号和小段原文：[检查脚本](../../scripts/verification/host-peer-command-inspect.cjs)。结合 r25 的[依赖拓扑](../attachments/public-validation.md)，可解释 8 个 missing peer：profile-local `node_modules` 缺少这些包，而桌面宿主内置了版本匹配的包。r25 的[原始静态检查](../attachments/public-validation.md)仍是退出码 **1**；本轮没有把它改写为通过，也没有删掉或降级 WH 的 peer 声明。

## 结论边界

此证据说明**当前桌面打包版的命令范围**，不构成 DSH 对第三方插件 peer 的长期兼容承诺，也不证明其他安装形态可运行。实际隔离 Web 与宿主服务加载 rc.3 的证据仍见 r24–r29。生产代码及安装包未变，故没有重复类型检查、构建和 271 项回归。G4/T18 仍为 **partial**；后续重点转向隔离 UI 会话恢复与子代理/压缩入口，而不再把这 8 项警告当作未知来源问题。
