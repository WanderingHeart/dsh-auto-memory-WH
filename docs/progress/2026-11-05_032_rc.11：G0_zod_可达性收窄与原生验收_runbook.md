1. 判定“宿主自带 zod 4.4.3 落在 GHSA-mrhx-c7xc-m3w5 受影响范围”对插件面是否有静态可达路径，并把结论收窄到可复核的边界；

## 1. G0 静态分析

公告（OSV `GHSA-mrhx-c7xc-m3w5` / CVE-2023-54404）：zod ≤ 4.6.5 在缺少长度约束的数组 schema 上校验超大受限集合时，`$ZodArray` 对每个失败元素累积 issue，可导致内存耗尽；修复版本 4.6.6。宿主 zod 为 4.4.3，确在范围内。

检查路径与结论：

| 表面 | 观察 | 结论 |
| --- | --- | --- |
| 插件 bundle | `lib/index.js`、`lib/client.js` 均不 `import` zod；源码只用 `@deepseek-ai/schemastery` | 插件自身不执行 zod 数组校验 |
| 工具参数 | `@deepseek-ai/dsh-tools`（161962 B）无 zod，无 `safeParse`；用 `parameterSchemaSpecToJsonSchema` 把参数规范转为 JSON Schema 校验 | 记忆工具参数不进入 zod |
| 宿主 `/api` 信封 | `@deepseek-ai/dsh-client-connection` 用 zod 校验 `{type, rpcId, method, payload: z.unknown()}`；先 `request.json()` 再 `safeParse(body)`，非 JSON 直接 400，body 受 `maxRequestBodyBytes` 限制 | 信封无数组；payload 不透明，路由自行解析 |
| 插件 RPC payload | 插件自己 `JSON.parse` 并按字段校验，不 import zod | 无 zod 数组校验路径 |
| 宿主残余面 | 打包 `@deepseek-ai` 下 109 个模块含 `z.array(`，未加 `.max()/.length()` 的共 **942 处**（扫描器口径），集中在 `dsh-api-remotes`、`api-session-controller`、`plugin-manager` 等宿主自有 RPC 域 | 残余风险在宿主内部，未逐一追踪调用链 |

结论：**未发现从记忆内容或工具参数到宿主 zod 数组校验的静态路径**；插件面可达性为 false。G0 因此**收窄但不关闭**：公告的可触发性取决于宿主内部对超大未约束数组的调用，仍需随 DSH 升级到 zod ≥ 4.6.6 或由宿主侧复核；这与此前 r81 的判断一致（`consistentWithR81: true`）。

新增只读脚本 `scripts/verification/g0-zod-reachability.cjs`（Electron Node），9 项断言覆盖上表；实跑 `RESULT PASS`，证据 `docs/evidence/S05-rc11-g0-zod/reachability.json`（含 advisory 元数据、boundary、残余 top15、checks、`reachableFromPluginSurface: false`）。
