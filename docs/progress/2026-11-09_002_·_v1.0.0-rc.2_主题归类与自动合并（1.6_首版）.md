# R189 · v1.0.0-rc.2 主题归类与自动合并（1.6 首版）

- 日期：2026-11-09
- 版本：`1.0.0-rc.2`（上一版 `1.0.0-rc.1`）
- 范围：B 类 1.6「项目记忆按主题大类重组」的首版落地

## 1. 起因与设计决定

所有者要求把 B 类功能逐项完善，并先听 1.6 的两个方案：

- **A 项目内主题层级**：新增 topic 目录/字段并让所有写入口分类；能按主题分组与配额，但格式、迁移、回滚风险高。
- **B 扁平 + 自动合并 + 索引排序**：不改格式，复用已有相关性/合并能力；但不解决不同主题并列浏览。

折中并确认的规则：

1. 两个 scope 都有主题；**每条记录必须有 topic**，旧数据先迁移归类。
2. 同主题且相关性 **≥80%** → 自动合并，不询问，只提供撤销；**≥60%** → 面板待确认；跨主题高相关只询问。
3. 合并结果继承已审核（不降级），来源标记为被取代；撤销即恢复。
4. 小鲸鱼只用于提示；确认落点是面板队列。

## 2. 实现

### 2.1 主题注册表与记录字段

- `src/types.ts`：`MemoryRecord.topic?: string`。
- `src/topics.ts`：每个 scope 一份 `topics.json`（`id` + `title` + `note`），中文 id 可用；`normalizeTopicId`、`topicIdFromTitle`、`upsertTopic`、读写与坏数据清洗；`UNCLASSIFIED_TOPIC` 兜底。
- `src/store.ts`：解析/序列化 `topic`，非法 id 拒绝；更新时继承，显式空串清除；`reviewFingerprint` 不含 topic，改主题不会让已审核记录降级。

### 2.2 自动合并

- `src/auto-merge.ts`：eligibility 为“已审核 + 有主题 + 非 task/置顶/禁用 + 非 `未归类`”；同主题 ≥80 用并查集聚成簇，≥60 进询问队列，跨主题 ≥80 只询问；`apply` 写合并记录（继承 verified）、来源 superseded、账本 `auto-merges.json` 环 100；`undo` 恢复来源并删除合并记录。
- `src/index.ts`：`autoMerge: true` 开关；启动 20 秒后跑一次，会话固化成功后 2 秒再跑；只在 `merge` 功能档可用。

### 2.3 写入口与面板

- `memory_write` / `memory_patch` / 管理 API 的 `memory.write` / `memory.patch` 接受 `topic`。
- 自动总结写入：按注册表做词面匹配，未命中落 `未归类`（不参与自动合并）。
- 面板：记录行显示“主题：X”；“重复与合并”页新增自动合并区块（立即合并 / 合并这一组 / 撤销这次合并）。

### 2.4 迁移

- `.work/migrate-topics.mjs`：`--dry-run`、备份、5 个主题、逐条写回、校验无未归类。
- 本机实际执行：21 条全部归类（记忆插件 15、考研 3、身份 1、项目经历 1、协作方式 1）。

## 4. 边界与已知问题

- 词面匹配只是兜底：命中不了就落 `未归类`，不会凭空发明主题；需要人工在面板调整，或后续让总结模型直接选主题。
- 自动合并只处理已审核记录，且不会合并存在矛盾的内容（矛盾检测仍在更新路径，不参与自动合并）。
- 撤销窗口取决于账本环（100 条）；超过后只能从归档/审计恢复。
- `未归类` 记录不进入自动合并，避免把不相关的事实并在一起。
- 相关性阈值是词法评分，不等于语义；62 分的那组（合并记忆 vs 主题重组）语义相近但并未自动合并，保留人工确认。
