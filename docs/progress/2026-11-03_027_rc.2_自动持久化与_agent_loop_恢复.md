# S05 rc.2 自动持久化与 agent loop 恢复（r22）

日期：2026-11-03。状态：**partial**。目标是消除 r21 探针手动追加 JSONL 的限制。本轮只增加隔离验证脚本与证据；WH 生产代码、已安装 rc.2 包、日常 DSH 配置和真实记忆均未改动。

## 方法与结果

使用本机打包的 DSH 0.2.1-rc.5 `dsh-agent-loop`、`dsh-session`、`dsh-session-persistence-jsonl`、`dsh-compaction-basic` 和 `wh-s05` 中已安装的 WH rc.2。两个独立 Electron Node 进程共用项目 `.work/S05` 下新建的合成会话与记忆目录。测试移除常见密钥环境变量，拦截 `fetch`、HTTP(S)、TCP、TLS、UDP 出口；模型、计量服务为进程内替身。

1. 第一进程通过真实 `ctx.agents.create()` 建立 agent 与会话。WH 注入已审核的合成项目记忆。真实基础压缩引擎使用假模型生成摘要并替换消息表面。
2. agent loop 持有 JSONL 写句柄，后端自动接收 `session/event`。测试调用宿主 `ctx.sessions.flush()` 并销毁 agent；**没有手动调用后端 `append()`**。落盘前会话共 **14 条**事件。
3. 第二进程通过真实 `ctx.agents.resume()` 打开并恢复同一会话。压缩开始、摘要、结束事件仍在；派生消息含合成摘要，已压缩的旧消息不可见。恢复后的会话共 **15 条**事件，包括宿主恢复时新增的事件。
4. 已安装 WH 在恢复后重新注入当前源文件中的已审核记忆。两进程共 **2 条**渲染审计，均记录该记忆且注入字节数大于零。
