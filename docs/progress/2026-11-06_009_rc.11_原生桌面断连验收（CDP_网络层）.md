## 起因

T19 一直缺“原生断连”的现场证据。r74–r77 的 DevTools Offline 与旧 Request Blocking 规则都没有真正阻断保存：r75 离线后保存仍成功，r77 的 `*api/auto-memory-wh/*` 规则显示 `0 affected`，随后记录落盘。两次意外写入都已从隔离备份恢复，旧步骤已停用。

r106 完成后，原生侧只剩“动态关闭/断连”组合。本次目标不是复刻浏览器 DevTools，而是在隔离桌面实例上，用 CDP 的网络层阻断把保存请求真正挡住，并证明：

1. 阻断时保存请求在渲染层/网络层失败；
2. 失败时合成记录文件没有被改写；
3. 解除阻断后保存成功，且审核状态、置顶、静音与正文不被破坏。

## 方法

### 隔离实例

`scripts/verification/manual/native-disconnect.ps1` 负责启动一个**隔离**的桌面实例：

- 若本机仍有 DSH 在运行则直接拒绝（单实例锁，已有实测：主实例运行时另起实例会在数秒内退出）；
- 设置 `DSH_HOME=.work\S05\native-real-user-home`，并隔离 `APPDATA` / `LOCALAPPDATA`；
- `Start-Process` 带 `--user-data-dir=.work\S05\native-cdp-user-data --remote-debugging-port=9222`；
- stdout/stderr 重定向到 `.work\S05\native-cdp\logs\app-<时间>.out.log|err.log`；
- 轮询 `/json/version` 后执行 drill，结束后关闭该实例并透传退出码。

### 目标页选择（本次关键修复）

桌面首次启动显示的是欢迎页 `renderer/welcome.html`（`file://` 源）。它不是工作区：相对 `fetch('/api/...')` 必然报 `Failed to fetch`。前几次失败正是 drill 连到了欢迎页。

`scripts/verification/manual/native-disconnect-cdp.mjs` 现在：

1. 轮询 `/json/list`，**优先选择 `dsh-app://app/`** 目标；
2. 若只有欢迎页，则连欢迎页调用预加载桥 `window.dshWelcome.skip()`（等价 UI 的“稍后配置”，不保存凭据），等待工作区目标出现（40×500 ms）；必要时用 DOM 点击“添加 API Key → `#skip-key`”兜底；
3. 连上工作区后再等 `memory.read` 可用（60×500 ms），避免应用后端尚未就绪时的 503。

### 阻断与保存

- `Network.enable` + `Network.setBlockedURLs(['*api/auto-memory-wh*'])`，并监听 `Network.loadingFailed`；
- 读取记录 → 在阻断状态下用**与原文相同的正文**发起 `memory.write`（contentChanged=false，因此不会把 `verified` 降级为 `candidate`）；
- 断言保存请求失败（`Failed to fetch`），且记录文件哈希不变；
- 解除阻断 → 重新读取 revision → 再保存同一正文（最多重试 4 次，409 时重读 revision）；
- 断言 HTTP 200、文件哈希与 revision 变化、正文/status/pinned/disabled 保持原样。

> 为什么用“同正文写”：`MemoryStore.write` 无论内容是否变化都会原子写入并更新 `updatedMs`，但只有 description/body/type/title 变化时才会把 `verified` 降为 `candidate`。同正文写既能证明“保存真的发生了（revision/哈希变化、HTTP 200）”，又不会破坏审核证据链；这样就不需要“写入测试文本再还原”的补偿写，避免二次降级。

- `cdpBlockLeaked: false`，阻断期间没有泄漏写入；
- `beforeHash c15c3c04…` 来自本次运行前的干净记录；运行后记录仍是干净 UTF-8，`updated: 1793942965011`，无锁/journal/tmp 残留。

## 过程中修掉的三个问题（供后续参考）

1. **欢迎页不是工作区**：`file://` 欢迎页上的 `/api` 请求必然失败；必须选 `dsh-app://app/` 目标，或在欢迎页调用 `dshWelcome.skip()` 进入工作区。
2. **启动期 503**：桌面页面的 `/api` 由 main 转发给内置 Web 服务；后端未就绪时协议处理返回 503。drill 必须先等 `memory.read` 可用，再判阻断。
3. **表达式错误导致的假 PASS**：早期把 Promise 当函数调用（`(…)()`），页面抛 `TypeError: … is not a function`，却被当成“阻断成功”。现已改为 `.then/.catch`，并且在阻断无效时通过“文件是否被改写”识别泄漏。

另外，失败尝试留下的根锁/`MEMORY.md` 锁与半截 journal，用 `releaseStaleLock`（`writersStopped: true`）+ `recoverTransactions` 清理，合成记录已恢复为 `verified/pinned/disabled` 且正文干净。
