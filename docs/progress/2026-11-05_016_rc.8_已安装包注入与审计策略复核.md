## 数据、安全与结论

探针仅向自己启动的 `127.0.0.1` 服务发送认证 API 请求，并调用本地 DSH 组装接口；未配置或调用模型。没有对整个进程做独立出站流量抓取，因此只断言**探针显式请求与模型路径**的范围，不声称网络完全隔离。合成记录与审计留在 `.work`；仓库中只保存不含登录 Cookie 或本机页面令牌的结果 JSON。探针退出时释放宿主服务。没有触碰原生桌面 profile 里的 `native-ui-synthetic`。

本轮把“当前 rc.8 已安装包在实际 DSH 宿主中执行审核筛选、注入组装和审计接口”标为**隔离通过**。`render_attempt` 只证明组装尝试，不能证明模型最终收到或采纳；原生桌面“查看组装审计”页面、真实 UI 会话、断连草稿和真实模型仍是剩余项。下一步需先设计不使用真实密钥的原生页面审计入口和可复核合成会话；无法形成安全可操作路径时，应明确记录边界，而非把本轮宿主探针当作桌面 UI 结果。
