# r191 — v1.0.0-rc.4：同主题自动合并门槛降到 60%

- 日期：2026-11-09
- 版本：`1.0.0-rc.4`（交接序号 r191）
- 目标：按所有者要求，把自动合并的相关性门槛从 80% 扩大到 60%
- 状态：已切版、已隔离验收、已升级日常桌面（待重启生效）

## 1. 目标与范围

rc.2 的自动合并分两档：同主题相关性 ≥80% 自动合并、同主题 ≥60% 进入面板待确认、跨主题高相关只询问。所有者本次要求“把自动合并的相关性限制范围扩大到 60%”，即让同主题 60–79% 这一段也直接自动合并。

本次只改门槛与相应文案/测试，不改合并算法本身，也不放开跨主题的自动合并：

- 同主题（两条记录 `topic` 相同）≥60%：直接自动合并，来源标记为被取代，可撤销；
- 跨主题 ≥80%：仍只进入面板“待确认”，不自动合并；
- 继续只处理“已审核 + 有主题 + 非任务/置顶/禁用 + 非未归类”的记录。

选这个切法的原因：跨主题的词面相似更容易是噪声（例如都提到“记忆”“测试”），而 60–79% 在同主题内通常意味着同一件事的不同写法；把跨主题询问保持在 80% 可以避免把两类不同的主线误并。

## 2. 实现

- `src/auto-merge.ts`：`AUTO_MERGE_SCORE = 60`；删除 `ASK_MERGE_SCORE`，新增 `CROSS_TOPIC_ASK_SCORE = 80`；扫描循环里同主题用 `>= AUTO_MERGE_SCORE`，跨主题用 `>= CROSS_TOPIC_ASK_SCORE`；注释同步为 rc.4 语义。
- `src/index.ts`、`src/management-api.ts`：相关注释改“同主题 ≥60 自动；跨主题 ≥80 询问”。
- `src/client/ManagementPage.tsx`：区块标题改“自动合并（同主题 ≥60%）”，说明补“跨主题 ≥80% 只进入下方待确认”；待确认标题改“待确认（跨主题 ≥80%）”。
- `tests/auto-merge.spec.ts`：新增 60–79 分同主题用例（75 分进入自动合并、待确认为空）与跨主题同分用例（75 分既不自动也不进待确认）。
- 文档：`docs/configuration.md`（两处）、`docs/attachments/roadmap.md`（1.6 进度与 1.7 P4 表述）、`CHANGELOG.md`（`1.0.0-rc.4` 段）。
- 版本号 4 处：`src/identity.ts`、`package.json`、`package-lock.json`（两处）。

本次不新增配置开关：门槛仍是常量，“可撤销”沿用账本（最近 100 条）。

## 4. 未测边界

- 真实数据上的自动合并要等 DSH 完全退出重开后、启动 20 秒的对账才会发生；本次升级路径不读写记忆，因此“升级当刻”不会合并任何记录。重启后，rc.2 报告里那组 62 分同主题记录将进入自动合并范围，可在面板“重复与合并”的账本里撤销。
- 相关性仍是词面匹配（ASCII 词 + 中文二元组），60 分附近可能有语义相近但用词不同的漏合并，也可能有字面重合但语义不同的误合并；本次只用合成用例覆盖 75 分带，未评估真实语料的误并率。
- 跨主题仍不做无同意合并；如果所有者希望跨主题也自动，需要另立一版并先看真实样本。
- 隔离验收覆盖的是打包/安装/存储/宿主探针，不包含“真实 62 分那组自动合并”的端到端观察；这一条留给重启后的面板核对。
