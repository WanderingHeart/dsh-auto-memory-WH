# r193 — v1.0.0-rc.6：跨端主题字段与“保留双方”冲突策略

- 日期：2026-11-09
- 目标：roadmap 1.2 首刀（三端导入导出与冲突合并）
- 候选：`dsh-auto-memory-wh-1.0.0-rc.6.tgz`，197,633 字节，sha256 `13f1b114f9b6d037d30148fa52786cd2c8cedf09a1668e86684a800adffb688b`

## 1. 目标与范围

1.2 的现状是：导出包（`wh-memory-export` v1）与同步变更集（`wh-sync-changeset` v1）已能跨端传输记录，但有两个缺口。

1. **主题字段没有进协议**：`topic` 是 rc.2 新增的章节归属，只存在本地记录里；跨端后另一端看到的是“未归类”，人物弧光与自动合并都会失真。
2. **冲突只有两种结果**：`skip`（保留本地、丢弃远端）或 `remote`（远端覆盖、本地降级为候选）。想“两边都留下”只能手工复制，容易丢内容。

本版做两件最小的加法：

- 导出包与变更集携带 `topic`，写回时原样落地；旧包/旧端点缺省即“未归类”，不丢正文。
- 新增 `onConflict: "fork"`：本地已审核记录不动，远端内容另存为可审核的 `<name>-shared-<指纹6位>` 候选。副本名由内容确定，同一变更集重复应用只得到 `skipped`，不会增殖。

不做：面板里的 JSON 包导入/导出 UI、冲突预览界面、自动合并两端内容——留到 1.2 下一刀。

## 2. 实现

- `src/transfer.ts`
  - `ExportRecord.topic?: string`，`buildExportPackage` 映射 `topic`，`applyImport` 正常写入带 `topic`。
  - `verifyExportPackage` 校验 topic 格式（`[\p{L}\p{N}][\p{L}\p{N}_-]{0,31}`）；坏 topic 整包拒绝，与坏任务字段一致。
  - `sharedForkName(name, record)`：`sha256(canonicalJson({title,description,body,type,topic}))` 前 6 位，名字截 48 字并去掉尾随 `-`，拼 `-shared-<digest>`。
  - `applyImport(..., onConflict: 'skip' | 'reject' | 'fork')`，结果新增 `forked: string[]`；fork 写 candidate，标题加“（另一端的版本）”，保留 topic 与任务字段，`pinned`/`disabled` 归 false。
- `src/sync.ts`
  - `SyncRecord.topic?`、`mapRecord` 带 topic、`verifyChangeset` 校验、三处写入带 topic。
  - `applyChangeset(..., onConflict: 'manual' | 'remote' | 'fork')`，结果新增 `forked`；fork 语义与导入一致（远端另存候选，本地不动）。
- 入口接线：`src/endpoint.ts` 与 `src/sync-flow.ts` 的 options 类型加 `fork`；`src/management-api.ts` 的 `sync.apply` / `import.apply` 接受并透传 `fork`；`src/maintenance-cli.ts` 的 `sync-pull` / `sync-apply` 同样接受 `fork`。
- 文档：`docs/attachments/sync-protocol.md` 增加 §3.4（主题字段）与 §3.5（冲突策略表），`CHANGELOG.md` 增加 rc.6 条目。

## 4. 未测边界

- 面板仍只有 Markdown 导出；JSON 包的导入/导出仍走 API 与 CLI，冲突预览 UI 未做。
- `fork` 之后需要人审核、合并或删除副本；自动合并不会自动吸收 fork 出来的候选（它只处理已审核记录）。
- 旧版本（rc.5 及更早）收到带 `topic` 的包会忽略该字段，不报错——这正是期望的向后兼容，但意味着旧端看不到章节归属。
- 跨设备只用合成端点与隔离 profile 验证；第二台真实 DSH 主机、真实 relay 网络仍未实测。
- 桌面升级时 DSH 仍在运行，进程内存里仍是 rc.5；需完全退出重开才会加载 rc.6。
