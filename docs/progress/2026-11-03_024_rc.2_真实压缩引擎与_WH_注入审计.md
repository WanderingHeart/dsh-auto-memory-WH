## 压缩与记忆行为

探针给真实 `SessionStore` 写入两个已完成的合成回合，然后调用真实基础压缩引擎的 `compactNow`。假计量使一个旧节点进入可压缩范围，假模型只返回本地固定摘要。引擎完成一次表面替换，写入 `compaction/start`、`compaction/summary`、`compaction/end`，替换了 **1 个**旧节点，并调用了一次会话 flush 监听器。派生消息中可见摘要和保留的新回合，不再包含被替换的旧回合。这是**真实宿主压缩事务**；模型、计量、维护 agent 和 flush 目标是隔离替身，未执行用户界面的 `/compact` 命令或真实持久后端写盘。

WH 在压缩前后均从当前源文件组装同一条已审核的合成项目记忆，片段相同且不超过 4096 UTF-8 字节。随后外部语义修改该源文件，下一次组装为空，旧审核不被压缩恢复。插件关闭并排空队列后，审计正好有三条：压缩前后两条非零 `render_attempt`，字节数一致；外部修改后一条 0 字节记录，排除原因为 `candidate`。这覆盖了用户要求的压缩后注入与审计检查。
