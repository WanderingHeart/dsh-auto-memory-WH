## 执行顺序（批准后）

1. 正常桌面用户保存并退出 DSH，确认无 DSH 进程。运行[受限操作脚本](../../scripts/verification/native-desktop-plugin.ps1)的默认 `Check`；只有返回 `ready-for-isolated-desktop-install` 才继续。脚本已通过语法检查，自动化账户的 `Install` 请求已被拒绝，**正常用户安装分支尚未执行**。
2. 手动断开外网。显式运行 `-Action Install -OfflineConfirmed`。脚本用内置 CLI、固定本地 tarball、`--offline --ignore-scripts` 和项目内 pnpm store 安装；不调用全局 CLI，不授予版本兼容豁免。首次失败后，已把既有隔离测试缓存的四个依赖元数据文件复制到桌面专用缓存，并在操作脚本加入哈希检查。离线缓存仍缺依赖时停止并保留现场，不切换在线安装。
3. 若命令成功，脚本检查 profile 声明依赖、选中 WH bundle、实际包版本 `0.1.0-rc.8`。再独立核对清单/锁文件与合成记忆目录；**此时只算安装成功，不算 UI、登录或模型请求通过**。
4. 后续需要在同一隔离环境按受控方案重新启动 DSH，验证 WH 页面、注入与审计。首次空白启动脚本拒绝复用目录，因此要先制定并验证单独的续启方案；不得直接重跑它。离线状态下登录失败是已观察到的宿主行为，WH 原生 UI 验收可能需要额外的认证测试方案，不能临时输入真实密钥。
5. 结束测试后，无 DSH 进程时用脚本 `-Action Remove -OfflineConfirmed` 经内置 CLI 卸载 WH。pnpm 11 的 `remove` 不接受 `--offline --ignore-scripts` 命令行参数；修正后的脚本只传受支持的 `--store-dir`，离线与禁用脚本要求由当前子进程的 `npm_config_offline=true`、`npm_config_ignore_scripts=true` 环境承担，并要求人工断网。核对依赖、bundle 选择和 WH 模块均已消失，再比较四个基线文件与备份。若卸载失败、锁文件或模块留下不一致，停止使用该隔离根并保留日志与目录；不手工删模块、覆盖原 profile、修改日常目录或重复盲试。可新建另一个全新测试根继续排查。

`-OfflineConfirmed` 是人的断网确认，脚本不能测量所有出站请求。打包管理器若进入失败补偿，官方代码可能恢复 manifest/lockfile 但留下下载的模块；因此所有失败都须核对清单、锁文件、模块和日志，不能只看退出码。项目内备份是核对/恢复依据，**不是**直接覆盖正在使用的 profile 的自动回滚程序。

## 授权边界

本方案只请求在上述项目 `.work/S05/native-real-user-home` 的隔离桌面 profile 中安装本地 rc.8、验证，再卸载/保留现场。不会安装到日常 DSH，不读取或迁移真实记忆，不使用真实模型密钥，不发布。桌面 UI/认证/模型路径的实际验收需后续确认测试条件与数据路径。
