# S05 v0.9.0：任务提醒回归宿主原生（r173）

## 1. 动机

到 v0.8.10，任务提醒有两套真源：记忆库里的 `type: 'task'` 记录，以及通过调度桥接复制到宿主 `schedule` 的镜像。桥接带来 sidecar 对账、幂等、孤儿清理与投递窗口等一整套复杂度，但用户实际只想要“一句话建提醒、到点响一下、完了就忘”。

所有者在 m07934 拍板：任务只存在宿主原生“自动化任务”，不再写入记忆库；保留一句话建提醒、小鲸鱼气泡与完成后清理；旧任务记忆迁移归档。m08081 授权开工。

## 2. 改动

### 2.1 新增 `src/reminders.ts`

- 纯函数层：`reminderTiming`（未来 `at`、过去 `after 60s`、`dueAt` 与 `inSeconds` 互斥、最小 60 秒）、`reminderPrompt`/`reminderTaskTitle`（标题前缀 `记忆提醒：`、正文标记 `[memory-wh] reminder`）、`isMemoryReminder`（双命中才认领）、`createReminder`/`deleteReminder`/`listDueReminders`（只认本插件标记、`[now-30min, now+60s]` 窗口、升序、上限 20）。

### 2.2 工具

- 新增 `memory_remind`：`title` 必填，`inSeconds`/`dueAt`/`prompt`/`newSession` 可选；默认 `target: {kind:'session', sessionId}`，`newSession` 时 `{kind:'new_once', create:{cwd}}`；宿主服务缺失时返回 `REMINDER_UNAVAILABLE`，不再静默降级。
- `memory_write` 的 `type` 枚举移除 `task`，schema 直接拒绝；execute 内保留一句防御性错误，提示改用 `memory_remind`。

### 2.3 服务端与面板

- `src/index.ts` 重写任务接线：`getSchedule`、`remind`、`dueReminders`；删除调度桥接、sidecar 对账定时器与记忆任务注入段；`scheduleStatus` 变为 `{available, mapped: 0}`。
- `src/management-api.ts`：`MEMORY_TYPES` 回到四个；`memory.write`/`memory.patch` 不再接受任务字段；`groups.list` 默认隐藏已取代；`tasks.due` 改为把 `dueReminders()` 映射成小鲸鱼需要的形状。
- 面板：移除任务类型、任务四字段控件、任务状态行与“标记完成/取消/重新打开”；“存储”抽屉的调度行改为“已连接（任务提醒走原生‘自动化任务’）/ 不可用：memory_remind 会明确报错”。
- 删除 `src/schedule-bridge.ts` 与 `tests/schedule-bridge.spec.ts`。

### 2.4 迁移

- `.work/archive-tasks-090.mjs` 把 user scope 中剩余的 1 条旧任务（`whale-pr-followup`）版本化归档；迁移前 22 条、迁移后 21 条、`type === 'task'` 剩余 0。
- 证据：`docs/evidence/S05-v090/task-migration.json`（含每条任务的 revision 与归档 id，可恢复）。
- 宿主 `schedule.json` 中已存在的桥接任务不受影响，继续按原生调度投递。

## 4. 边界与未做

- 任务不再进入记忆库，因此没有记忆侧的备份、跨设备同步与审核；原生“自动化任务”页新建的任务同样不在记忆库。
- `whale-pr-followup` 已被归档；它的宿主调度仍会按 2026-11-09 20:00 投递提醒，但记忆库不再保留下一次跟随。
- `type: 'task'` 仍在类型、同步、导出与面板类型筛选里保留“只读兼容”，由旧数据决定，不新增。
- `tasks.due` 的窗口与去重逻辑未变；小鲸鱼插件缺失时客户端不注册定时器。
- 关闭/重开补投的长期演练仍未做。
