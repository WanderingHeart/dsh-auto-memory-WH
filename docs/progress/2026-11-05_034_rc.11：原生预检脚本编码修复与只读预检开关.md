# S05 rc.11：原生预检脚本编码修复与只读预检开关（r89）

- 时间：2026-11-05
- 状态：候选 `dsh-auto-memory-wh@0.1.0-rc.11` 未发布；本轮只修复核脚本与 runbook，未改产品代码，未重新打包。
- 相关：[发行前清单](2026-11-06_018_发行前门槛清单.md)、[原生 rc.11 runbook](2026-11-05_008_rc.11_隔离桌面原生验收_runbook（所有者执行）.md)、r87。

## 起因

所有者按 runbook 第 1 步执行预检：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verification\native-desktop-plugin.ps1 -Action Check -PostRemoveBaseline
```

Windows PowerShell 5.1 在第 107/146/118/110 行报 `UnexpectedToken`、`字符串缺少终止符`、`语句块中缺少右“}”`，中文提示同时显示为乱码。

## 根因

三个原生脚本（`native-desktop-plugin.ps1`、`native-desktop-wh-resume.ps1`、`native-desktop-isolated.ps1`）此前是 **UTF-8 无 BOM**。PowerShell 5.1 在没有 BOM 时按当前 ANSI 代码页（本机 936/GBK）解码；UTF-8 的多字节序列被拆成两个 GBK 字符，部分尾字节落进字符串定界符或转义位置，于是词法解析直接失败——这不是脚本逻辑错误。r87 当时只用「按 UTF-8 读文本再 `ParseInput`」验证语法，掩盖了实际执行环境的解码差异。

## 修复

1. 三个脚本重写为 **UTF-8 带 BOM**（`UTF8Encoding($true)`）。
2. 用所有者同款 Windows PowerShell 5.1 的 `Parser::ParseFile` 逐个验证：三者均 0 错误，中文正常显示。
3. 为只读预检增加 `-AllowRunningDsh` 开关：
   - 仅 `-Action Check` 可用；与 `Install`/`Remove` 同用时直接拒绝。
   - 严格预检（不带开关）在 DSH 运行时仍然拒绝，行为不变。
   - 输出增加 `runningDsh`（实际进程数）与 `runningDshAllowed`，供证据记录。
4. runbook 更新：预检的 `runningDsh` 期望、可选的只读预检命令、删除“改用 pwsh”的旧兜底、注明脚本必须保持 UTF-8 BOM。

## 验证

- `Parser::ParseFile`（Windows PowerShell 5.1）：三个脚本均 `OK`；BOM 均为 true。
- 只读预检（本机 DSH 打开，`-AllowRunningDsh`）：exit 0，输出
  `status = ready-for-isolated-desktop-reinstall`、`archiveSha256 = 0AEC562A…B3B49`、`installed = false`、`baselineMatch = true`、`runningDsh = 7`、`runningDshAllowed = true`。
- 严格预检（不带开关）：exit 2，输出“DSH 仍在运行；先正常退出测试窗口，或仅对只读预检使用 -AllowRunningDsh。”。
- `-Action Install -AllowRunningDsh`：exit 2，输出“AllowRunningDsh 只用于只读预检；安装/卸载必须先关闭 DSH。”。
- 产品代码、测试与候选包未变（最近一次 `npm test` 仍为 281/281；此后只改 `.ps1`/`.md`）。

## 教训

- `edit`/`write` 文件工具会把 `edit` 目标重写成无 BOM UTF-8；**每次编辑这几个 ps1 后必须重新补 BOM 并用 5.1 解析复验**，否则所有者一运行就语法错误。
- 复核脚本的语法验证必须使用所有者实际使用的 PowerShell 版本与解码路径；`ReadAllText` + `ParseInput` 只能验证“字符串形式”的语法，不能证明文件执行可用。
