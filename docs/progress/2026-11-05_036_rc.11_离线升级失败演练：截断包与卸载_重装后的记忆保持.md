# S05 rc.11 离线升级失败演练：截断包与卸载/重装后的记忆保持

> 时间：2026-11-05。
> 状态：完成一轮**隔离副本上的离线失败演练**；不构成真实 DSH 升级或原生桌面验收。

## 起因与目标

§15.3 第 7 条要求“卸载/重装/更新失败证明数据保持”，T17 生命周期行仍记“磁盘满及其他中断阶段仍待测”，G4 行仍把“升级故障恢复”列为缺口。用户（m02434）指示“先完全离线推进吧”，因此在不触碰日常 DSH、不联网的前提下，用隔离副本验证：**一次失败或中断的安装/卸载尝试之后，记忆目录是否逐字节不变，且已装版本是否仍可用。**

## 方法

- 从 `.work/S05/installation-home`（含已安装 rc.11 与 9 个合成记忆文件）复制出 `.work/S05/upgrade-failure-drill`，每次运行脚本都重建副本。
- 复制后重写 `profiles/wh-s05/node_modules/.modules.yaml` 的 `storeDir`/`virtualStoreDir`：pnpm 按**字符串**比较存储路径，副本若不改写会在任何操作前报 `ERR_PNPM_UNEXPECTED_STORE`；存储目录随副本一起复制，因此只需改记录路径。
- 用 rc.11 包的前 2048 字节生成 `upgrade-failure-drill-artifacts/corrupt-rc11.tgz`，作为确定性的“无效本地包”失败源（`ERR_PNPM_Z_BUF_ERROR ... unexpected end of file`）。
- 记忆基线：9 个文件的 SHA-256 聚合、文件数、事务 journal 与残留锁；每一步之后重新计算并比对。
- 步骤：A 已安装状态下安装截断包 → B 卸载 → C 卸载状态下再装截断包 → D 重新安装 rc.11 → E 恢复后再装一次截断包。

每一步均无 `.wh-transaction.json`、无残留 `.lock`。卸载与重装均可在完全离线条件下完成（隔离 profile 的 pnpm 元数据缓存含 `@deepseek-ai/schemastery`、`yaml` 等记录）。

## 观察与教训

- 失败发生在 pnpm 取包/解包阶段，早于任何对记忆目录的写入，因此记忆不可能被半写；这与 r83 的“锁超时发生在 journal 之前”是同一类边界。
- 同一实测包路径重复 `add` 会得到 “Already up to date”；本演练用**不同路径**的截断包，确保 pnpm 真正尝试并失败，而不是被“已是最新”短路。
- 复制隔离安装家时必须重写 `.modules.yaml` 的绝对存储路径；仅创建指向原 store 的 junction 无效（pnpm 不解析真实路径）。

## 边界

- 全部为合成记忆、隔离副本、离线本地失败；**没有**验证真实 DSH 版本的在线升级、pnpm 元数据/缓存损坏、安装中断的各个阶段、物理磁盘满或断电。
- 截断包只代表“无效本地包”一类失败；真实升级失败可能发生在解包之后的链接/构建阶段。
- 未涉及原生窗口、模型接收或真实用户记忆。
- 一次性副本，不改变 `wh-s05` 本身；候选包未变（`0AEC562A…72CB3B49`）。
