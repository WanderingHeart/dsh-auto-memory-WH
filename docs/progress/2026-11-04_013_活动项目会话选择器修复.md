# S05 活动项目会话选择器修复（r36）

日期：2026-11-04。状态：**partial**。目标版本仍为工作树 `0.1.0-rc.3`；已安装的 `wh-s05` rc.3 包未升级。

## 问题与原因

r35 的 403 来自两种不同的会话视图：浏览器原下拉框直接读取客户端持久会话列表，只要有 `cwd` 就展示；WH 服务端只认 `agent/created` 后仍有效的 `projectSessions` 映射，并在 `session/disposed` 时撤销。于是历史会话可见，但当前没有活动 agent 时，选它必然得到 `SCOPE_DENIED`。这是选择器展示范围与授权范围不一致；不能把客户端保存的 `cwd` 直接当作服务端授权。

## 工作树改动

服务端新增需宿主认证的只读 `sessions.active` 路由，只返回当前映射中再次通过 `resolveProject` 核对的会话 ID 与目录。WH 面板初次打开及定时刷新时从该路由更新下拉框；选中的会话失效后自动清空选择。原有所有项目读写接口的服务端范围检查保持原样，不从浏览器传入任意目录。

改动位于 [服务端入口](../../src/index.ts)、[管理接口](../../src/management-api.ts)和[页面](../../src/client/ManagementPage.tsx)。[接口回归](../../tests/memory-api.spec.ts)覆盖活动会话过滤、额外参数拒绝及认证拒绝。类型检查、构建均通过，完整回归 **272/272** 通过：[测试结果](../attachments/public-validation.md)。

## 边界与下一步

这是**工作树修复**，并非已安装 rc.3 的浏览器验收。还需封装新候选版、在 `wh-s05` 离线升级，实测会话关闭/重开后的下拉框，并完成回退与合成记忆哈希核对。历史会话没有活动 agent 时仍不能直接编辑项目记忆；若未来支持离线历史项目管理，需单独设计可信的宿主会话加载与目录确认流程。日常 DSH、真实记忆及模型凭据未使用，G4/T18 保持 **partial**。
