# S05 逐文件扫描分解与并发原型（r06）

日期：2026-11-03。状态：partial。本轮只新增合成基准脚本和证据；生产读取路径、格式、候选包没有修改。

## 逐文件耗时

对 2000 条合成记录重复 5 次，复现 scanSync 的单文件循环，分别计时路径校验、lstat、readFileSync、parseMemory。第一次约 1795 ms；后四次约 1449–1623 ms。后四次读文件约 907–1032 ms、路径校验约 261–288 ms、解析约 253–280 ms，lstat 约 18–20 ms。原始数据见 [scan-profile.json](../attachments/public-validation.md)。该测量未包含目录/格式标记/锁检查、最终注入，计时调用本身有开销，不能当作完整 scanSync 的精确分摊。

读盘是最大部分；仅优化排序或 lstat 难以让 2000 条达到低延迟。直接省略路径校验、读取缓存索引或只按 mtime/size 判断外部修改，都会改变当前安全与信任语义，本轮没有采用。

## 限并发读取原型

只在合成目录上用现有 inside + readRegular 逐文件核验并解析，分别用并发 1/8/16 读取，每组 3 次，均获得完整 2000 条有效记录。并发 1 为 2485–3613 ms，并发 8 为 1126–1222 ms，并发 16 为 978–1113 ms。[原始结果](../attachments/public-validation.md)。原型没有覆盖根格式标记、事务锁、并发写入竞态和宿主同步 Prompt 接口，因此不能直接替换正式代码，也不能与上节同步循环作等价速度承诺。

## 进入实现前的门槛

要改正式扫描，先确认宿主注入回调是否接受异步读取，以及在写入或外部修改与读取重叠时如何维持可判定的快照。需要验证目录链接替换、文件读前后身份/内容变化、格式标记、项目范围、候选降级、字节预算、审计和故障返回。若宿主只接受同步 text 函数，异步原型不能接入；需考虑预取但每次组装仍应有可靠的外部变化检查，并证明不会将旧 verified 内容重新注入。
