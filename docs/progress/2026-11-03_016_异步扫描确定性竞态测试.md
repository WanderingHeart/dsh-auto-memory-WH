# S05 异步扫描确定性竞态测试（r11）

日期：2026-11-03。状态：partial。scanAsync 仍是独立试验接口，正式 Prompt 不调用它；旧 rc.0 tgz 不包含本轮代码。

## 改动与验证

scanAsync 原先用 Promise.all：一个并行工作单元报错时，函数可先返回，其他读取仍在后台继续。本轮改为等待所有工作单元 settle，再将首个错误汇总为 storage-unavailable。失败时不返回任何已读出的记录。

新增可控暂停点测试，暂停的是测试中的文件打开操作，不进入产品代码：

1. 文件已列入扫描清单，但打开前被删除。结果为 `{records:[],issues:['storage-unavailable']}`，不将已读出的已审核记录当作完整集合。
2. 文件打开前被外部改为同字节数的不同正文，并恢复原修改时间。读取到新内容后，原审核指纹不再匹配，状态降为 candidate；不靠 mtime/size 继承信任。

全套 **266/266 项、22 文件**，类型检查和构建通过。[测试 JSON](../attachments/public-validation.md)。无真实记忆、模型密钥或官方配置写入。

## 仍未证明

测试证明这两个受控时序，并不代表文件在打开后被同权限进程恶意替换、目录联接点在读取期间变化，或两个作用域间原子快照已经解决。异步扫描也未接入最终 waterfall 与 render_attempt 审计。因此 G4 与大库性能目标仍开放。下一步需把最终注入失败路径和审计事件一起做隔离集成，再决定新候选版本和安装验收。
