## 3. 改动讲解

身份对应关系如下，集中定义后可减少前后端名称不一致的问题。

| 用途 | 当前值 |
|---|---|
| 项目显示名称 | dsh-auto-memory-WH |
| npm 技术包名 | dsh-auto-memory-wh |
| 插件与面板 ID | auto-memory-wh |
| API 根路径 | /api/auto-memory-wh |
| 词典命名空间 | autoMemoryWH |
| Prompt section | memory-wh:index |
| 样式前缀 | dam-wh- |
| 默认数据子目录 | memory-wh |

保留 `memory_*` 工具名以兼顾已有调用习惯。WH 加载时发现七个工具名中任意一个已被占用，便在创建存储前拒绝加载。此保护只覆盖 WH 后加载的情况；旧插件随后加载时未必执行相同检查。因此配置中仍只能启用一个记忆插件。

`maxBytes` 默认 4096；原任务书的 `maxIndexBytes` 可作为别名。例如仅配置 `maxIndexBytes: 8192`，最终预算为 8192；两个键不相等时拒绝配置。当前开发版暂时拒绝小于 4096 的预算，以避免上游极小预算行为与最终规格不符；S04 应用完整渲染测试取代此限制。

默认存储改为宿主解析的 `DSH_HOME/memory-wh`，属于相对总规格候选共享目录的明确调整，详见 ADR 0001。合成测试在旧 `memory` 目录放置标记，调用 WH 写入后确认新记录位于 `memory-wh`，旧标记保持不变。没有用真实记忆进行此测试。

原存储格式、核心工具和大部分业务代码继承上游。新增独立身份、配置归一化和冲突保护，不把继承功能计为原创。默认自动总结改为关闭。核心 DSH peer 明确接受 `0.1.5-rc.2 || 0.2.1-rc.5`，避免把普通版本范围对预发布版本的判断当成兼容依据；这不等于完整桌面产品兼容认证。

## 7. Token、成本与性能

规格给 S02 的开发预算为 **5,000–10,000 输入加输出 tokens**，属于规划估计。当前工具未提供可核验的本阶段模型输入、输出、缓存或计费统计，因此实际消耗写为 **不可获取**；不从报告字数推算消耗，也无法判断是否超预算。

没有为测试调用模型总结。自动总结默认关闭。实际宿主合成片段为 1381 UTF-8 字节，其 token 数没有 tokenizer 或 usage 实测；字节数不换算为确定 token 数。请求延迟、吞吐和峰值内存尚未做基准。

下一阶段 S03 暂沿用规格 **10,000–20,000 tokens** 的规划估计；事务、并发或宿主接口差异导致范围扩大时，在阶段报告记录重新估算的原因。
