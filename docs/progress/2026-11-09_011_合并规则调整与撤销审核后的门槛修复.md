# r198 — v1.0.0-rc.11：合并规则调整与撤销审核后的门槛修复

- 日期：2026-11-09
- 目标：`1.0.0-rc.11`
- 候选：`.work/dsh-auto-memory-wh-1.0.0-rc.11.tgz`

## 1. 目标与范围

1. 按所有者新规则调整自动合并触发条件：
   - **同主题且相关 ≥60%** → 自动合并；
   - **同主题或相关任一 ≥60%**（只满足一项）→ 只进面板“待确认”；
   - 两者都不达标 → 不处理。
2. 修复 rc.10 撤销“用户审核”后遗留的 `verified` 门槛回归：
   - 自动合并、导入冲突、同步冲突、质量提示此前只对 verified 生效，candidate 记录被静默绕过；
   - 统一改为“权威记录 = 非 disputed、非 superseded、非停用”；冲突改为“内容不同且本地更新不早于远端”。

不在本版：跨主题的语义级自动合并（仍登记未排期）；导入历史/冲突差异预览；真实第二设备与 relay 联调。

## 2. 实现

- `src/auto-merge.ts`：`AUTO_MERGE_SCORE = 60`、`MERGE_ASK_SCORE = 60`（移除 `CROSS_TOPIC_ASK_SCORE`）；`eligible` 不再要求 verified；配对判定：`sameTopic && relatedEnough → auto`，`sameTopic || relatedEnough → ask`。
- `src/transfer.ts`：`planImport` 以 `remoteMs <= localMs` 或本地 disputed/superseded 判冲突；只有远端严格更新才覆盖。
- `src/sync.ts`：`applyChangeset` 同样按 `updatedMs` 判冲突；删除分支按 `deletedAtMs` 与本地更新时间比较；`onConflict: 'remote'` 仍可强制覆盖。
- `src/quality.ts`：`verified-stale` → `stale-record`，对 candidate/legacy 也提示。
- `src/client/ManagementPage.tsx`：`verified` 文案改“系统确认”；自动合并/待确认标题与说明按新规则改写。
- 测试：`auto-merge` 默认 candidate 并新增“只满足一项→ask”“都不达标→忽略”；`transfer`/`sync` 新增 candidate 冲突与远端更新用例；`quality` 改测 `stale-record`。
