# S05 rc.11 可重复验收入口（r86）

> 时间：2026-11-05（Asia/Shanghai）。状态：**completed（合成数据、本机隔离、仅 127.0.0.1、无模型调用、未发布）**。本轮把此前散落的构建、打包、分发、许可与宿主探针收束成一个可重复运行的入口 `scripts/verification/acceptance-suite.mjs`，并在 `wh-s05` 已安装 rc.11 的隔离环境中完整跑通。

## 起因

r80–r85 的验收证据由多条手工命令拼成：`npm test`、`npm pack`、`package-smoke`、分发/许可审计、以及需要 `ELECTRON_RUN_AS_NODE=1` 的宿主探针。任何一条漏跑或版本参数写错，都只能靠报告文本发现。用户按序指令的第三步是“把现有探针整理成可重复运行的验收入口”，因此本轮新增一个入口并把它作为后续候选的默认验收方式。

## 入口设计

- `scripts/verification/acceptance-suite.mjs [version]`：默认从 `package.json` 取版本；校验 `0.1.0-rc.N`，并由版本推导证据阶段 `S05-rcN`。
- 固定步骤：`typecheck` → `build` → `unit` → `pack` → `package-smoke` → `distribution` → `license`。`pack` 重新生成候选包并写入 `docs/evidence/S05-rcN/{package.json,hashes.json}`，因此分发/许可审计总是针对**同一份刚打出的包**，不会读到旧 tgz。
- `--with-host` 追加：宿主组装/审计探针（fresh 生命周期 + policy matrix）、已安装会话生命周期、peer 拓扑、宿主依赖清单。运行前强制校验 `wh-s05` 已安装版本与目标一致，不一致直接失败并提示重装。
- `--skip-build` 可跳过重建；`unit`、`host-*` 失败时返回非零退出码。
- 汇总写入 `docs/evidence/S05-rcN-acceptance/summary.json`（含每步耗时、退出码、摘要，以及 tgz SHA-256）。
- 原有单点脚本保持可用（详见 [scripts/verification/README.md](../../scripts/verification/README.md)）；入口不安装、不卸载候选包，安装仍由 `isolated-cli.ps1` 手工完成。
- 为支持任意 `rc.N`，`host-audit-bridge-probe.cjs` 增加 `--installed-version <v>`，`candidate-distribution-audit.mjs` 与 `runtime-license-audit.mjs` 的候选正则放宽为 `/^rc\.\d+$/`。

## 对门槛的推进

- **T21/G5：** 验收现在有单一入口和机器可读汇总，减少“报告说跑过、实际漏跑”的风险；不改变任何门槛的通过状态。
- **G0/G1/G2/G3/G4：** 无新增覆盖；入口只是把 rc.10/rc.11 已有证据的复跑方式固定下来。
- **G4：** 仍未通过；原生桌面、原生断连、主动组装与模型接收仍需用户安排。

## 边界

- 入口不安装/卸载候选包，不接触真实记忆或日常 DSH；`--with-host` 依赖已安装的 `wh-s05`。
- 仅本机 Windows + 打包宿主；未在原生桌面、真实设备或断网/断电条件下运行。
- 分发/许可审计依赖 `npm audit` 与本地锁文件，仍受离线/注册表状态影响（本轮 0 告警）。
- 包仍为 `private: true`，未发布。

## 结论

后续候选只需“安装到 `wh-s05` → 运行一条 acceptance 命令”即可复现同类证据；但入口不能替代原生桌面、真实迁移和公开发布验收。

**v0.1.0 工作量粗估仍约 85%**；G4 与公开发布门槛未变。
