## 1. 动机

r131–r133 已经有“导出包、变更集、信封、签名与加密”，但还缺少一个**载体可以直接照着实现的契约**：

- 载体应该搬什么、不该改什么；
- 游标存在哪里、何时推进；
- 失败与重试的语义（至少一次投递、幂等应用）；
- 冲突与信任错误如何呈现。

第 4 项不引入真实浏览器扩展或移动端（不在本仓库），而是把协议固定下来，并提供一个可运行的本地端点桩，让未来载体只实现“搬运”部分。

## 2. 实现

### 2.1 端点契约（`src/endpoint.ts`）

```ts
interface SyncEndpoint {
  readonly deviceId: string
  readonly scope: 'user' | 'project'
  changes(since?: number): Promise<Changeset>
  seal(changeset: Changeset, recipient: string): SyncEnvelope
  apply(envelope: SyncEnvelope, options?: { onConflict?: 'manual' | 'remote' }): Promise<ApplyResult>
  state(): Promise<SyncState | null>
}
```

`createLocalEndpoint()` 组合 `MemoryStore`、`buildChangeset/applyChangeset` 与身份/信任：

- 不传 `since` 时读本地游标文件；首次为 0；
- `seal()` 只接受信任列表内的收件人；
- `apply()` 校验收件人、信任、签名、变更集校验和，成功后把游标推进到 `until`；
- 重复应用同一信封幂等（同内容进 `skipped`）。

### 2.2 协议文档（`docs/attachments/sync-protocol.md`）

面向载体作者的契约：角色与边界、端点接口、信封/变更集字段、生命周期、错误码表（`UNTRUSTED_SENDER`、`WRONG_RECIPIENT`、`BAD_SIGNATURE`、`CHECKSUM_MISMATCH` 等）、适配清单（原样传输、允许重放、大文件上限）与已知未实现（传输层、配对、轮换、分片）。

## 3. 验证

### 契约测试 `tests/endpoint.spec.ts`（5 项）

1. 导出→封装→应用，记录落为 candidate，游标推进到 `until`；
2. 同一信封重放，`created=0`、两条 `skipped`；
3. 错误收件人/未信任发送方被拒；
4. 本地已验证且内容不同 → `conflicts` 保留本地；`onConflict:'remote'` 覆盖并降级 candidate；
5. 向未信任收件人封装被拒。

### 演练 `scripts/verification/sync-envelope-drill.mjs`（9/9 PASS）

A/B 身份与互信 → A 导出两条记录 → 封装给 B → B 应用（2 条 candidate）→ 游标推进 → 重放幂等（2 skipped）→ B 本地改并审核 alpha → A 的信封报冲突且本地保留 → `remote` 覆盖并降级 → 篡改密文 `BAD_SIGNATURE` → 第三方收件人 `WRONG_RECIPIENT`。

证据：`docs/evidence/S05-v040-sync/envelope-drill.json`。
