# S05 v0.3.0 并发写入可观测性（r130）

时间：2026-11-07
状态：已实现并验证；候选包未重建。

## 起因与目标

v0.3.0 第 4 项要求“锁等待/恢复/降级指标在面板可见”。写入路径此前只在错误中暴露原因，用户无法判断一次保存为什么慢、是否遇到锁竞争、审计是否降级。

## 实现

- 新增 `src/metrics.ts`：进程内计数器（写入次数、失败次数、锁超时、忙/恢复错误、累计/最长/平均写入耗时、恢复次数、备份次数），`recordWrite` 按错误文本分类，`resetMetrics` 供测试。
- `src/store.ts`：公开的 `write` 作为计时包装，内部逻辑改名为 `writeInternal`；成功与失败都计数，不改变原有语义。
- `src/management-api.ts`：新增 `memory.metrics`（POST），返回 `{metrics, audit, storage}`；只读，不触发维护操作。
- `src/client/ManagementPage.tsx`：工具栏“运行指标”，区段显示写入/错误/锁超时/忙/恢复/备份与审计降级、存储可写状态。
- `src/auto-backup.ts`：自动备份成功后计数。

## 验证

- `tests/metrics.spec.ts` 3 项：计数与均值、锁超时/忙分类、恢复与备份。
- `tests/memory-api.spec.ts`：`memory.metrics` 返回写入计数与存储快照。
- `tests/management-page.spec.tsx`：点击“运行指标”显示进程指标。
- `npm run typecheck` 通过；`npm test` **35 文件 357/357**（12.50s）。

## 边界

- 指标是**进程内**的：重开 DSH 清零；maintenance CLI 的维护/恢复操作不计入面板计数。
- 锁超时与忙分类依赖错误文本，若宿主改写错误信息会退化为“其他错误”，不会误报成功。
- 未构建 `lib/`、未重打候选包；日常安装仍是 0.2.0，面板要看到“运行指标”需 0.3.0 构建并安装。
