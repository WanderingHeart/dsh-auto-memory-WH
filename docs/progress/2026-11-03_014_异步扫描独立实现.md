# S05 异步扫描独立实现（r09）

日期：2026-11-03。状态：partial。工作树仍标记 0.1.0-rc.0；以前打包的 rc.0 tgz 不含本轮代码。本轮未安装或发布新包。

## 完成内容

在 MemoryStore 增加独立的 scanAsync 试验接口，以最多 16 个并行工作单元读取当次源文件。它仍使用现有的路径约束和 readRegular 读前/读后身份及大小检查；检查 WH 格式标记，保留结果顺序，读取前后检查事务锁、格式标记和目录文件名清单。任一不可判定错误返回 storage-unavailable，避免把部分集合当作完整记录。接口当前没有接到 Prompt、工具或管理 API，正式行为仍使用 scanSync。

## 验证结果

新增 3 项直接比较同步与异步扫描的测试：已审核记录及外部语义改动降级、32 条并行读取顺序、未知格式和锁冲突失败关闭。全套 **262/262、22 个文件**，类型检查、构建通过。[测试 JSON](../attachments/public-validation.md)。

对现有 2000 条合成记录直接调用 scanAsync 5 次，分别为 1044、904、897、1213、995 ms；全部读出 2000 条，无 issue。[原始基准](../attachments/public-validation.md)。这是扫描接口耗时，不能与完整 Prompt 组装或真实模型请求延迟等同；和上轮同步数据也不是严格同条件 A/B。

## 尚未达到的门槛

目录清单复查与每文件读前后检查缩小了竞态窗口，但不能证明整个 2000 文件集合具有原子快照语义；当前同步版本也不提供完整原子快照。新增接口尚缺大库中途写入、删除/重命名、目录链接替换、超额/损坏文件、项目同名跨范围和取消时的对抗性验证。目录文件名复查还需核对 Windows 大小写与重排行为。不得把它直接接入 waterfall 或把 0.9–1.2 秒宣称性能达标。

下一步补齐上述对抗性用例，建立“扫描失败则不注入”的完整链路测试，再接入异步组装与审计；之后才重打新版本包并做 wh-s05 升级验收。G4、真实数据、模型压缩和子代理验收仍开放。
