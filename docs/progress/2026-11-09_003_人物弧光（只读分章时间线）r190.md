# S05 · v1.0.0-rc.3 人物弧光（只读分章时间线）r190

- 日期：2026-11-09
- 阶段：S05 / 1.7 P3（第一刀）
- 结论：**已切版、已构建候选、隔离 22/22、日常桌面已升级（7/7）**；重启 DSH 后生效。

## 1. 目标与范围

把用户层（`_user`）与全部项目 scope 的记忆按“主题成章、章内按时间排序”串成一条可追溯的叙事线，用来回答“这个人一路是怎么走过来的”，与 v0.10.0 关系图回答的“此刻谁和谁相关”区分开。

所有者的三项选择（2026-11-09）：

1. 第一刀只做**只读分章时间线**，不做“生成叙事草稿”，不调用模型、不做 embedding（零 token）。
2. 分章维度：**主题为主、时间为次**。
3. 数据范围：**跨 scope 合成一条完整人生线**（`_user` + 所有项目 scope）。

只读边界：不写记忆、不合并、不改信任状态；接口不返回正文；解析失败只计入 `skipped`，超过 2000 条截断并标记。

## 2. 实现

- 新模块 `src/arc.ts`：
  - `arcOriginLabel(slug, cwd?)`：用户层显示“个人”，项目取 cwd 末段，缺 cwd 时退回目录 slug。
  - `mergeTopics(registries)`：按出现顺序合并各 scope 的 `topics.json`（用户层在前），去重。
  - `buildArcView(records, topics, {sources, skipped, truncated, now})`：章节顺序 = 注册表顺序 → 未登记主题按中文名称排序 → `未归类` 最后，只保留有记录的章；章内 `at = createdMs ?? updatedMs ?? 0` 升序，未知时间排末，再按 name；标出 `status`、`supersededBy`、`supersedes`、来源与来源路径。
  - `scanArc(rootDir)`：先读 `_user`，再遍历根下 `--*--` 项目目录（`withFileTypes` 天然不跟随符号链接），读 `.wh-project.json` 取 cwd、读各 scope 的 `topics.json`，用 `readRegular` + `parseMemory` 读记录，排除 `MEMORY.md`；解析失败 `skipped++`，超过 `MAX_ARC_RECORDS = 2000` 截断。
- 只读 API `arc.view`（`src/management-api.ts`）：POST，接受 `scope/sessionId` 以兼容面板传参但忽略；复用 `features.graph` 门控（与关系图同属“全功能档”），不新增档位键；返回 `chapters/total/skipped/truncated/sources/generatedMs`，**不含正文**。
- 面板（`src/client/ManagementPage.tsx`）：工具栏“关系图”旁新增“人物弧光”；只读视图显示篇章数/记忆数/来源统计、每章 `<section>` 与条目（日期、标题、来源、信任状态、取代关系），点击条目跳回该记忆（并按 `originPath` 匹配项目会话）；“返回列表”关闭。`src/client/index.ts` 增加对应 CSS。
- 测试：`tests/arc.spec.ts`（10 项：章节顺序、章内排序、updatedMs 兜底、取代链、空章丢弃、截断、主题合并、来源标签、扫描容错）+ `tests/arc-api.spec.ts`（4 项：200/章节内容/不返回正文、未知字段 400、minimal 档 403）+ 管理页测试扩展（篇章渲染、时间顺序、取代文案、点击跳转、返回列表、minimal 档不显示入口）。
