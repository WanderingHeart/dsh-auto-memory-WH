# DSH 原生桌面隔离验收方案（空白启动已完成）

日期：2026-11-04。目标：DSH Desktop `0.2.1-rc.5` nightly、WH `0.1.0-rc.8`。正常用户空白桌面启动已完成，见[r58](2026-11-04_035_rc.8_正常用户空白桌面启动.md)。WH 在隔离桌面 profile 的离线安装与功能性卸载已完成，见[r62](2026-11-04_039_rc.8_隔离桌面卸载复核.md)；登录和插件原生页面等端到端验收尚未执行。下方首次启动命令保留供历史对照；四个测试目录现已存在，**不要直接重跑**。

项目提供[隔离检查/空白启动工具](../../scripts/verification/native-desktop-isolated.ps1)。默认只检查、不启动；只有显式传入 `-Launch -OfflineConfirmed` 才尝试空白 DSH 启动。工具不结束既有 DSH 进程、不安装 WH、不修改原程序 ACL 或系统环境变量。`-OfflineConfirmed` 是操作者人工确认已断开外网，**不是工具对网络隔离的测量**。受限自动化账户的安全拒绝和正常桌面账户的空白启动均已有结果；该工具不用于复用现有测试目录。

若要执行，先保存工作并从日常 DSH 正常退出，确认任务管理器中不再有 `DeepSeek Harness` 进程。在开始菜单打开普通 PowerShell 窗口（**不要以管理员身份运行**），先输入以下命令；它只做检查，不启动：

```powershell
& "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-isolated.ps1"
```

只有结果显示 `ready-for-blank-host-only`，才临时断开外网，再在**同一个窗口**输入下面的命令：

```powershell
& "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-isolated.ps1" -Launch -OfflineConfirmed
```

当前自动化账户下旧版 `powershell.exe` 的执行策略拒绝直接运行此脚本；上面使用的是本机已核对可执行的 PowerShell 7 路径，不修改系统执行策略。若任一步报错、出现异常弹窗或程序没有打开，保存文字/截图并停止，不要重复执行或改权限。若出现空白 DSH 窗口，不登录、不安装 WH、不发送消息；查看后从窗口正常退出。最后恢复网络，将两条命令的输出和窗口情况发回。成功启动也只算空白宿主周期通过，后续必须复核隔离目录和桌面 profile 才能继续。

## 已知事实与待验证假设

- r48 的隔离启动在 profile 创建前出现 Electron `install_dir_access.cc:52` 和 `0x80000003`；原安装权限未改。r49 的源码核对说明报错文字不足以证明具体 ACL 原因。
- r52 的自动化命令身份为 `tony\codexsandboxoffline`，与正常桌面用户可能不同；该差异**可能**影响受限令牌读取，但没有证明它就是崩溃原因。
- 打包主程序在初始化时调用 `app.requestSingleInstanceLock()`，第二实例可把参数交给既有窗口；这个调用早于主流程。依赖 `--user-data-dir` 将单实例行为彻底隔离尚无本机证据。因此首次正常用户试验必须在**所有现有 DSH Desktop 进程退出后**进行，且先验收空白隔离桌面，不能借已有日常窗口观察结果。
- `wh-s05` 是独立 CLI 测试 profile，不能视为桌面 profile。后续只读核对证明内置 CLI 的**插件命令**可以管理已初始化的 `desktop` profile；普通配置导出入口仍拒绝。见[r59](2026-11-04_036_rc.8_隔离桌面安装准备.md)。

## 执行门槛：任何一项不满足即停止

1. 由正常交互式桌面用户执行，并记录 `whoami`；不得用 `tony\codexsandboxoffline` 的自动化会话启动 GUI。启动前核对 DSH Desktop 进程数为 **0**。关闭日常 DSH 是用户操作；不要由测试脚本结束现有进程。
2. 在项目 `.work/S05/` 下新建**全新且空白**的 `native-real-user-home`、`native-real-user-data`、`native-real-appdata`、`native-real-localappdata`。启动前核对四个绝对路径均在项目 `.work/S05/` 内，不指向用户日常 DSH、AppData 或 `wh-s05`。任一路径已存在时先检查内容，绝不盲删。
3. 只在本次启动进程的环境中设置 `DSH_HOME`、`APPDATA`、`LOCALAPPDATA`，并传入独立的 `--user-data-dir`。不修改用户级/系统级环境变量，不更改原程序目录 ACL，不关闭 Chromium 沙箱，不改 `app.asar`。
4. 删除**子进程环境副本**中的真实模型密钥和云服务凭据；隔离目录只放合成文本。任何需联网的验证先列明端点并用本机假模型/计量服务；原生启动阶段先断开外网或设置经核实的出站限制，保留本机回环。没有抓包或等价证据时，不能宣称所有请求均留在本机。
5. 记录原版 `DeepSeek Harness.exe`、`app.asar` SHA-256、精确版本、启动用户、进程 ID、启动时间、四个隔离路径和运行日志位置。只核对测试目录是否出现 profile；不读取日常记忆内容。

## 五个验收周期

| 周期 | 操作 | 可接受证据 | 失败时处理 |
|---|---|---|---|
| ① 启动前边界 | 检查用户身份、零既有 DSH 进程、路径空白、包指纹、子进程环境和出站限制 | 脱敏检查记录；不包含密钥值 | 停止，不启动 |
| ② 空白桌面启动 | 正常用户从隔离环境启动**未安装 WH**的原版桌面，观察空白 profile 与退出 | 窗口/日志、隔离目录清单、无日常目录写入证据 | 若仍触发异常，保存日志与弹窗，停止后续周期；不改 ACL 或沙箱 |
| ③ 安装前审查 | 确认桌面确实使用预期 `DSH_HOME`，明确桌面 profile 的安装入口、备份、卸载和回滚步骤 | profile 根与操作路径的只读证据 | 不明确则停在此处，不把 `wh-s05` 安装结果当作桌面安装 |
| ④ WH 桌面生命周期 | 隔离 profile 安装与功能性卸载已获授权并完成；原生页面、注入、审计、会话关闭重建、页面编辑/冲突/断连仍待受控续启与登录方案 | 请求端点清单、插件清单、脱敏日志、页面/存储结果 | 保留合成数据，按已核对的步骤回退；不转向日常 profile |
| ⑤ 清理与复核 | 退出测试进程，核对测试包、合成记忆及原日常目录无意外变化；记录异常和恢复结果 | 前后哈希/目录清单、进程数、阶段报告 | 有偏差时先保存证据，停止任何真实数据操作 |
