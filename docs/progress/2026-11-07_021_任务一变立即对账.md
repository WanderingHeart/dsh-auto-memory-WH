# r147 — v0.5.2：任务一变立即对账

- 日期：2026-11-07
- 阶段：S05 / v0.5.2（任务变更即时对账）
- 前置：[r146](2026-11-07_020_真实桌面验证：桥接落位与对账滞后.md)（发现对账滞后约 3 分钟）、[r143](2026-11-07_017_真实宿主投递核对_+_任务完成即归档.md)（完成即归档）
- 触发：所有者指示“验证完就任务一变就对账吧”

## 1. 动机

r146 在真实桌面观察到：任务创建 20:07:25，宿主 `schedule.json` 到 20:10:27 才出现该任务。0.5.1 的对账只有“启动 +10s / 每 5 分钟 / `agent/created` 60s 节流”三种触发，于是：

- 提前完成的任务可能在宿主侧仍保持 `active`，到期仍被投递；
- 完成后的宿主清理最多滞后 5 分钟。

0.5.2 把“任务一变”变成对账触发器，把上述时间窗从分钟级降到秒级。

## 2. 实现

### 2.1 变更回调

- `src/memory-tools.ts`：新增 `MemoryToolsOptions { onTaskChange?: () => void }`；`memory_write` 成功后判断 `touchesTask = type === 'task' || existing?.type === 'task'`，完成归档分支与普通返回前都调用；`memory_delete` 先读取旧记录判断是否任务，删除后调用。非任务写入不触发。
- `src/management-api.ts`：`ManagementConfig` 新增 `onTaskChange`；`memory.write`、`memory.patch`、`memory.delete`、`memory.review` 在任务成功变更后调用（`memory.review` 取 `store.review` 的返回值判断类型）。

### 2.2 对账并发守卫

- `src/index.ts` 的 `reconcileTasks` 增加 `reconciling` 标志：上一次对账未结束时直接返回，结束后在 `finally` 复位，避免短时间多次写入叠加出重叠的宿主调用。

### 2.3 接线

- `registerMemoryTools(ctx, store, config.enableUserScope, { onTaskChange: reconcileTasks })`；
- `registerMemoryApi` 配置增加 `onTaskChange: reconcileTasks`。

调度仍由原有触发器兜底（启动 +10s、每 5 分钟、`agent/created` 60s 节流），即时回调只是加快任务相关变更。

## 4. 未覆盖与边界

- 真实点击“标记完成 → 宿主 tasks 立即清空 → 21:00 不投递”需要重启 DSH 后在面板完成；本报告先记录到“已装上桌面”，点击验证单独补记。
- 即时回调是“尽力而为”：宿主不可用时仅记录日志，任务仍留在记忆真源，由定时对账兜底。
- 并发守卫会丢弃重叠触发，极端情况下某次变更要等下一次对账（最坏 5 分钟）；这是为了不放大宿主调用。
- 宿主 `schedule` 仍是内部接口，无公开类型；升级宿主可能改变行为。
