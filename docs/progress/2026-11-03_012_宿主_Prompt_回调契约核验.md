# S05 宿主 Prompt 回调契约核验（r07）

日期：2026-11-03。状态：partial。仅新增本机宿主契约核验脚本和阶段记录；产品代码、候选包及记忆数据未改变。

## 本机实测契约

核验对象为本机 DSH 0.2.1-rc.5 nightly 内置的 @deepseek-ai/dsh-system-prompt 0.2.1-rc.5。安装包源码中，section 的 text 函数在组装段落时直接执行 `section.text(context)` 并将返回值存入 `assembly.sections[].text`，没有 await。后续 `renderPrompt` 将 text 当字符串处理并读取 `text.length`。Agent loop 虽然 await 整体 `systemPrompt.assemble`，但那是段落 text 已取值后的异步 waterfall，不能据此推断 text 回调支持 Promise。

[契约检查结果](../attachments/public-validation.md) 用断言固定上述表达式。源代码副本只保存在被忽略的 .work/S05/host-reference，不纳入候选包。本结论限定此本机 build，没有调用真实模型，也不代表其他 DSH 版本。

## 对 r06 原型的影响

r06 的限并发读取原型返回 Promise，不能直接放到当前 `ctx.systemPrompt.section({ text })`。直接替换会把 Promise 当作段落文字，导致渲染路径不符合契约。当前同步扫描仍保留外部修改即时可见、逐条审核指纹验证及范围隔离；不能为了速度直接信任旧缓存。

可继续调查的方向是宿主 `system-prompt/assemble` 异步 waterfall 是否允许先用空的同步段，再在事件中异步读取并安全替换该段。这需要验证事件顺序、重复调用、审计 render_attempt 次数、文本转义/预算、会话取消和关闭、跨项目隔离，以及实际载体与类型契约。另一方向是预取加可靠的内容版本失效，但必须证明外部同大小/同 mtime 改动不会错误保留 verified。两条都还只是设计候选，未实现。

## 验收结论

已关闭“异步 text 回调可直接接入”的假设；2000 条低延迟门槛和 G4 仍开放。下一步先做合成宿主 waterfall 原型与对抗性修改测试，确认是否可以在不改变信任和审计语义的情况下执行异步组装；若不成立，保留现有同步正确路径并明确规模上限。
