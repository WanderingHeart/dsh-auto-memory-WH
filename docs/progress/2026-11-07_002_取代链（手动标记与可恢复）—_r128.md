# S05 v0.3.0 取代链（手动标记与可恢复）— r128

- 时间：2026-11-07
- 范围：v0.3.0 / 5.2 第 3 项“冲突与取代”的第一块（手动取代链；主题合并建议仍待做）
- 状态：实现与测试完成；未构建 lib、未打包、未切版本

## 1. 背景

r127 之后，注入排序与跨会话召回已可解释，但“同主题多条记忆谁替代谁”仍只能靠自动总结时隐式发生；面板没有手动入口，用户无法显式表达“B 取代 A”。本步只做**手动、可恢复、同 scope** 的取代链，不做自动合并、不做模型改写。

## 2. 改动

### 2.1 存储层 `src/store.ts`

新增 `supersede(name, scope, cwd, expectedRevision, successorName)`：

- 双方名称先规范化为 canonical name；
- 拒绝自取代（`Cannot supersede a record with itself`）、源不存在（`NOT_FOUND`）、revision 不符（`Revision conflict: reload before superseding`）、源已取代（`Record is already superseded`）、继任者不存在（`SUCCESSOR_NOT_FOUND`）、继任者已被取代（`Successor is itself superseded`）；
- 先在源记录写 `status: superseded` + `supersededBy`，再在继任者补 `supersedes`（保留继任者原状态），事务内两次原子写；
- 不删除、不改正文、不写审计事件；返回更新后的 `{source, successor}`。

### 2.2 管理 API `src/management-api.ts`

新增 `memory.supersede`（POST）：

- 入参：`scope`/`cwd`/`sessionId`（common）、`name`、`expectedRevision`、`successor`、`confirm`；
- `confirm !== true` 返回 `INVALID_INPUT: 需要明确确认取代关系。`；
- 成功返回 `{ok:true, source, successor}`。

### 2.3 面板 `src/client/ManagementPage.tsx`

- `Row` 增加 `supersededBy?` / `supersedes?`；
- 列表行状态行显示“被 X 取代”“取代了 Y”；
- 编辑器工具栏在“已保存且未取代”时显示“标记为被取代”，用 `window.prompt` 输入同范围继任者名称，POST 后关闭草稿；不提供批量或自动推断。

## 3. 语义与边界

| 项 | 行为 |
| --- | --- |
| 方向 | 源 → 继任者；继任者保留自己的 status 与正文 |
| 范围 | 仅同一 scope（用户/项目），不做跨 scope |
| 可恢复 | 不删除文件；清除链接即恢复为原状态（需另行编辑，本轮未做界面） |
| 审计 | 本轮不写 `audit.jsonl` 事件（仅信任状态变化，注入会自动排除 superseded） |
| 自动性 | 无自动合并、无相似度推断；必须手动确认 |
| 链 | 允许 A→B→C；已取代者不能再作为源，也不能作为继任者 |
