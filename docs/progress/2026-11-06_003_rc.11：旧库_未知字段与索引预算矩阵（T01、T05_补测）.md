## T01：旧库与未知字段

脚本 `scripts/verification/legacy-unknown-fields-matrix.mjs` 在独立合成根中执行 14 项检查，全部通过：

| # | 场景 | 结论 |
|---|------|------|
| 1 | 未知标量/嵌套/数组字段 | `parseMemory` 收进 `metadata`，不丢 |
| 2 | `serializeMemory` 往返 | metadata、description、body 逐项不变 |
| 3 | 已知字段类型非法（`created: not-a-number` 等） | 静默忽略，不抛错，不进入 metadata |
| 4 | `__proto__` 形态的未知键 | YAML 解析与展开后 `Object.prototype` 未被污染 |
| 5 | `store.write` 更新（内容变更） | 未知 metadata 保留，不因重写丢失 |
| 6 | 无 `.wh-format.json` 的旧根（live） | 不信任任何记录：`scanSync` 返回空集；管理 API 另行把非空旧根标为只读 |
| 7 | 无 marker 旧根的 inventory | 记录被识别，无 issue（迁移可以读取旧根） |
| 8 | 迁移旧根 | 引导生成 v1 marker；记录文件逐字节不变；迁移后可正常 `scanSync`，未知字段仍在 |
| 9 | marker `version: 2` | inventory 报 `unsupported-format: .wh-format.json`；apply 拒绝 |
| 10 | 记录 `schemaVersion: 2` | 兼容读仍可解析，但迁移报 `unsupported-record-version`；apply 拒绝 |
| 11 | 非法 `status` 枚举 | live 回退为未审核；迁移报 `invalid-trust-status`；apply 拒绝 |
| 12 | 半截 `origin` | live 丢弃 origin；迁移报 `unrecognized-origin`；apply 拒绝 |
| 13 | 归档 → 恢复 | 文件字节哈希不变，未知 metadata 仍在 |
| 14 | CRLF frontmatter | 可解析，未知字段与正文保留 |

观察与边界：

- 未知字段是**保留**语义（`metadata` 原样回写）；已知字段类型非法则是**丢弃**语义——两者不同，报告里明确区分，避免把“容忍”误读成“保留坏值”。
- 无 marker 旧根在 live 读取下是静默空集，不是报错；真正的“只读”提示由管理 API 的错误码承担。迁移是唯一会引导补 marker 的路径，且记录字节不变。
- 迁移仍是严格读取：不静默修版本/信任状态；有 issue 的计划不会被 apply 接受。
- 未覆盖：带真实旧版工具产物的完整语料、审计/归档同时纳入迁移、跨版本真实升级。仍属合成矩阵。

## T05：索引段预算矩阵

脚本 `scripts/verification/index-budget-matrix.mjs` 在 41 条合成记录（含 CJK、破折号、emoji、pinned、candidate、disabled、stale、40 条普通记录）上，对 `maxBytes = 128/256/512/1024/1200/2048/4096/8192/16384` 执行 10 项检查，全部通过。实测：

| maxBytes | 实际字节 | 注入 | 截断 |
|---------:|---------:|-----:|-----:|
| 128 / 256 / 512 | 0 | 0 | 41 |
| 1024 | 904 | 2 | 39 |
| 1200 | 1115 | 3 | 38 |
| 2048 | 1959 | 7 | 34 |
| 4096 | 4069 | 17 | 24 |
| 8192 | 8078 | 36 | 5 |
| 16384 | 9080 | 41 | 0 |

- 所有档位 `textBytes ≤ maxBytes`，且 `Buffer.byteLength(text)` 与 `textBytes` 一致；无 U+FFFD，说明没有把多字节字符切断。
- `pinned` 在 1200 字节下仍排第一；排除原因稳定为 `candidate` / `disabled` / `stale`，其余未入选才是 `budget`。
- 截断标记与 `truncated.length > 0` 严格一致；预算低于框架本身时输出空段（0 字节），不抛错。
- 同步与异步路径在 9 档预算下逐字节一致；重复调用确定性一致；带 query 时 pinned 仍优先且不超预算；关闭用户作用域时只出现项目记录。

边界：

- 这里只证明**插件自有 `maxBytes` 段**不超预算、不切坏字符；宿主把这段拼进系统提示词后的总 token/字符预算仍由宿主决定，未在真实模型调用中测量（T05 仍不是“宿主全部 Prompt 预算”）。
- 记录集为合成，未覆盖真实记忆的极端分布（超长单条、全 pinned、全 stale）。
