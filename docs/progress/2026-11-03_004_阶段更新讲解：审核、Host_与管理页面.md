## 1. 这一阶段解决什么问题

原来的候选或未标状态记忆可能直接进入后续对话；页面编辑还未强制使用版本信息；审计按集合变化去重，无法反映每次组装尝试。S04 将这些行为连成一条明确的流程：**新建待审核 → 人工阅读确认 → 在完整字节预算内使用 → 每次组装留下有限审计**。

例如模型写入“项目使用某数据库”时，它先成为候选，下一轮不会自动带入。用户审核后才可进入索引。如果另一个编辑器已改变该记录，旧草稿的保存会被拒绝，页面保留草稿；外部修改正文也不能继续借用旧审核标签。

## 3. 改动讲解

### 审核与并发

新写入默认 candidate，模型工具不能发送 status/evidence 自授信任。UI 审核通过管理 API 明确确认；已审核内容有 reviewHash，外部更改名称/标题/摘要/类型/正文会使原指纹失效。revision 对应整份原文件字节，模型更新、删除和管理修改均必须提供当前值。归档恢复还会检查归档内容哈希，拒绝同名覆盖。

reviewHash 不是签名，无法对抗同权限恶意程序伪造；它解决的是旧审核随内容改变失效的问题。S03 原字节迁移、未知元数据保留和事务机制继续使用，没有通过重写旧文件来批量授予信任。

### 注入与审计

注入从当前源记录选取有效 verified，不从 MEMORY.md 缓存提取内容。最终片段包括边界、标题、策略、转义和截断提示；太小的预算返回空段。原本跨作用域同名记录在审计中使用不同身份，置顶不能绕过信任和预算。每次 assembly callback 都记录 render_attempt，重复集合也不去重；没有声称模型成功收到或使用记忆。

日志按默认 1 MiB / 7 天在后续追加时滚动，队列最多 256 条，详细选择/排除名单各最多 128 条。错误/拥塞计入进程内丢失计数，面板显示降级。没有收集原始会话 ID、cwd、正文、Prompt 或问题；名称仍是本地敏感元数据，不应公开。

### 管理面板

页面只列选定范围，项目需要用户选会话并由 Host 确认路径。草稿固定原范围，断网/冲突后保留，内容变化会取消审核勾选。归档先确认，恢复检查哈希。预览不执行 HTML，审计改为可读的字节/名单/原因，避免只展示技术 JSON。

已修复一次交互测试暴露的问题：打开归档/审计后触发刷新导致区域立即消失。现仅切换范围时清除这些视图。新 UI 目前为中文；英文 README 保留，不能据此声称面板已完整双语。

### 与上游的关系

继续复用 MIT 底座的文件模型、匹配与固化相关纯函数、Cordis 双端插件形式；WH 新增严格信任、预算、审计、管理 API 与页面模块。旧自动 Claude 扫描/导入路由、全项目浏览和 AGENTS 导出路由未在新管理 API 注册。部分上游纯函数保留用于回归或未来工作，不代表仍向 UI/模型暴露。

## 7. Token、成本与性能

规格中 S04 原预算为 10,000–20,000 输入加输出 tokens，是规划估计。当前工具没有可靠的实际输入/输出/缓存/计费数据，实耗 **不可获取**，不按代码长度倒推。

本阶段涉及管理页和信任链较大改写；S05 原 15,000–30,000 token 规划继续作为参考，实际加载器/权限适配如有新差距，先更新剩余工作估算。不是费用承诺或自动追加授权。

测试没有调用外部模型或自动总结；UI 列表/搜索/导出不主动调用 LLM，模型工具本身及返回内容仍可能占用上下文。实测仅报告探针 478 UTF-8 bytes；实际模型 tokenizer/usage、缓存收益、请求延迟、峰值内存尚未测量。250 项测试通过不是 2000 条记忆性能达标的证据。

每次组装读取当前文件、事务复制作用域、审计以有限文件重写方式滚动，都会增加本地 I/O。大规模记录/归档以及多进程压力仍待基准测试；不为提升速度取消一致性保护。

## 8. 已知问题、风险与假设

- **阻止真实使用：** 官方安装器、真实桌面认证/客户端载体、跨新会话与重启/压缩/子代理完整矩阵未测；实际拒绝/允许策略不可仅靠假载体证明。
- **继承的 G2/G3 缺口：** 未用授权真实副本；实际断电、网络盘、Windows ACL、同权限恶意目录竞态未完整验证。
- **审核边界：** 指纹无签名，名称仍出现在日志；自然语言过滤不等于防注入安全证明。直接调用底层 store 的可信插件代码有授予 verified 的能力，模型入口没有。
- **会话映射：** 项目需本进程看到 agent/created 后可管理，重启/旧会话未确认时拒绝访问；真实 UX 待 S05。
- **页面：** 草稿只在当前挂载页面内保留，刷新网页/退出应用会丢失；没有自动合并。归档未分页，中文新文案，尚无完整可访问性验收。
- **导出：** 采用 Markdown + 逐文件 JSON 清单，未实现 ZIP；连续双下载需真实载体验证。合并 Markdown 不是恢复备份。
- **审计：** 默认后续追加时清理旧行；进程计数重启重置，无法保证崩溃前队列全落盘；最多 128 项明细，超限有标记。
- **自动化：** 上游自动总结代码保留且默认关闭；其来源、预算、幂等及诊断完整验收属于 S07，本阶段不推荐开启。
- **发布：** private:true 与停用发布流程继续保留；依赖许可证全文/安全审计、作者署名、公开地址仍待准备。
