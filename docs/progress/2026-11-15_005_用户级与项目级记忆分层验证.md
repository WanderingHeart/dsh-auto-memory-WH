# 用户级与项目级记忆分层验证

日期：2026-11-15。版本：工作区 1.0.0-rc.17。仅验证当前实现，没有修改运行时代码或发布。

## 用户期望

类型 user、feedback、reference、project 是内容分类，均可包含跨会话有用的信息。项目级保存具体环境、过程与细节；同一项目的新会话复用。用户级保存跨项目概括，例如“用户之前完成过阿克曼小车项目”。不应把类型 project 等同于仅当前项目可用，也不应把项目详情直接复制成全局记忆。

## 实测结果

| 场景 | 结果 |
|---|---|
| 四种类型分别存入用户级，在两个项目生成注入索引 | 全部可见，类型不限制跨项目使用 |
| 项目 A 保存虚拟机信息，重新打开存储实例后在 A 读取、生成索引 | 细节保留，索引包含该记录 |
| 项目 B 读取、生成索引 | 不读取或注入 A 的项目级详情 |
| 关闭 enableUserScope | 用户级条目不进入索引 |
| 固化一条项目完成记录，再切换到另一个项目生成索引 | 项目级写入 1 条，用户级仍为 0 条，另一项目索引为空；没有自动概括 |

前四项支持当前分层存储机制；第五项确认用户期望尚未满足，不能写成“全部功能验收通过”。当前可显式写入 type=project、scope=user 的简短经历，但项目级内容不会自动衍生出这样的用户级记录。

代码复核：consolidate.ts 将候选写入一个作用域；其提示词还限定 user 作用域用于全局偏好、默认 project，与用户希望全局保留项目经历的要求不一致。injection.ts 根据作用域和当前 cwd 选择记录，不执行摘要或晋升。索引只包含名称/标题和描述；正文需工具读取，不能保证模型每次都会主动读取。

## 方法与边界

直接调用真实 src/store.ts、src/injection.ts、src/consolidate.ts，使用独立临时目录和合成数据；固化候选是固定模拟模型输出。重新创建 MemoryStore 验证持久化，不冒充真实 DSH 新建会话端到端测试。没有调用模型、运行 VM、访问用户日常记忆，也未证明模型会正确自动选择类型和作用域。当前项目身份依赖宿主提供的 cwd，不能将任意不同路径自动视为同一项目。

证据见 ../evidence/S05-scope-layering/result.json；脚本见同目录 test-scope-layering.mjs（使用当前本机源码路径，仅供复验，不进入发布包）。
