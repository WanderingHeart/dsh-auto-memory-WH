# r126 — v0.3.0 项目 scope 合并与归档

- 时间：2026-11-06 23:58（Asia/Shanghai）
- 阶段：S05 / v0.3.0 开发线
- 状态：5.2 第 1 项（盘点/重映射/合并/归档）完成
- 关联：`docs/attachments/roadmap.md` 5.2 第 1 项

## 1. 背景

盘点与重映射只解决“一个 scope 换 cwd”。两个工作区合并、或某个项目不再使用但想保留记录时，还需要把记录并入另一个 scope，或把整个 scope 退役保留。

## 2. 实现

- `src/projects.ts` 新增 `mergeProjects({root, fromCwd?, fromDirectory?, intoCwd, intoDirectory?, writersStopped, skipIdentical?})`：
  - 必须 `writersStopped: true`；两个 scope 都必须存在且标记合法；
  - 不能并入自身；
  - 复制前逐文件检查目标：同名且字节相同 → 仅在 `skipIdentical: true` 时跳过；同名不同字节 → 立即失败（无覆盖、无合并猜测）；
  - 先复制、逐对校验字节，全部通过后才删除源目录；任何冲突都在删除前中止；
  - 跳过 `MEMORY.md`、`.wh-project.json`、`*.lock`、`*.tmp`、`.wh-transaction.json`；
  - 返回 `{fromDirectory, intoDirectory, copied, skippedIdentical, skippedInternal, removedSource}`。
- 新增 `archiveProject({root, fromCwd?, fromDirectory?, writersStopped})`：
  - 必须 `writersStopped: true`；
  - 把整个 scope 目录移到 `<root>/_archive/projects/<dir>-<ISO>`，保留标记与记录；
  - 盘点跳过 `_archive`（所有 `_` 前缀目录都不作为项目 scope）；
  - 返回 `{fromDirectory, archiveDirectory, records}`；恢复 = 移回原目录并按需重写标记。
- `maintenance-cli` 新增 `project-merge` 与 `project-archive`；`docs/storage-recovery.md` 命令表补两行。

## 3. 验证

- `tests/projects.spec.ts` 扩到 9 项（新增 5 项）：
  - 合并：记录并入目标、源目录消失、盘点只剩目标；
  - 冲突：同名不同字节 → 失败且源保留；
  - 跳过相同：`skipIdentical` 下同字节跳过、独有文件复制；
  - 自身合并拒绝、未停写者拒绝；
  - 归档：目录移到 `_archive/projects`、盘点为空、记录仍可读；未停写者拒绝。
- `typecheck` 通过；目标测试 **9/9**。

## 4. 边界

- 合并只做“同 scope 命名空间内无覆盖的并集”，不做同名字段的自动取舍；`skipIdentical` 只接受逐字节相同；
- 归档保留原始标记（旧 cwd）；恢复到新机器/新 cwd 时需再跑 `project-remap`；
- 不改写审计历史与备份清单中的旧路径；
- 合并会连同 `.archive/<name>/` 归档一起复制（按目录递归），但不合并 `MEMORY.md`（派生文件，下一次写入重建）。
