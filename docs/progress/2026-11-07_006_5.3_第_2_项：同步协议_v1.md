# S05 5.3 第 2 项：同步协议 v1（r132）

时间：2026-11-07
状态：文件式变更集协议与双端离线冲突演练已落地；传输/认证/加密不在本项。

## 协议

```json
{
  "format": "wh-sync-changeset",
  "version": 1,
  "deviceId": "device-a",
  "scope": "project",
  "since": 0,
  "until": 1793983005621,
  "producer": { "name": "dsh-auto-memory-wh", "version": "0.2.0" },
  "upserts": [ { "name": "...", "description": "...", "body": "...", "type": "reference", "status": "verified", "updatedMs": 1793983005621 } ],
  "deletions": [ { "name": "beta", "archiveId": "...", "deletedAtMs": 1793983005700 } ],
  "checksum": "sha256(...)"
}
```

- 游标是毫秒时间戳：`since` 之后的更新与归档删除进入变更集；`until` 是本次最大值，作为下一次游标。同毫秒边界记录会重复出现，但应用按内容幂等跳过。
- 删除来自归档墓碑（`listArchive`），不是“文件消失”；因此离线删除也能传播。
- 校验和覆盖 deviceId/scope/since/until/upserts/deletions；限制 5000 条、8 MiB。
- 导入端：新记录写 candidate；本地已验证且内容不同 → 冲突（默认不动）；显式 `onConflict: remote` 才覆盖，覆盖后降为 candidate。删除已验证记录同样判冲突。
- 状态文件：`loadSyncState/saveSyncState`；CLI `sync-changes` 可传 `stateFile` 自动取 `cursor`，`sync-apply` 成功后写回 `{deviceId, scope, cursor: until}`。

## 入口

- API：`sync.changes`、`sync.apply`（必须带 `approvedChecksum`）。
- CLI：`sync-changes`（root/scope/deviceId/out，可选 stateFile/since）、`sync-apply`（root/file/approvedChecksum，可选 stateFile/onConflict）。
- 仍无面板按钮；UI 留给同步阶段。
