# S05 5.3 第 1 项：稳定的导出/导入包（r131）

时间：2026-11-07
状态：格式与入口已实现并验证；候选包未重建。

## 为什么

v0.4.0 的三端同步需要先把“一份记忆”变成可校验、可迁移的文件；已有的 `export.markdown` 只导正文，没有信任状态、校验和与导入冲突规则。

## 包格式

```json
{
  "format": "wh-memory-export",
  "version": 1,
  "createdAt": "2026-11-07T00:00:00.000Z",
  "producer": { "name": "dsh-auto-memory-wh", "version": "0.2.0" },
  "scope": "user",
  "records": [ { "name": "...", "description": "...", "body": "...", "type": "reference", "scope": "user", "status": "verified", "pinned": false, "reviewHash": "..." } ],
  "checksum": "sha256(...)"
}
```

- 校验和基于规范化 JSON（键排序、丢弃 undefined），所以“序列化→读回”不改变校验和；创建时间不参与校验。
- 限制：最多 2000 条、4 MiB；记录名、description 500、body 8000、type、scope 统一校验；重复名直接拒绝。
- 导入输出是 `candidate`，**不会**继承 `verified`/pinned/disabled；已审核且内容不同的记录判为冲突，默认不覆盖（`onConflict: skip` 也只跳过）。

## 入口

- API：`export.package`、`import.plan`、`import.apply`（后者必须带 `approvedChecksum`）。
- CLI：`transfer-export`（root/scope/out）、`transfer-plan`（file/root）、`transfer-apply`（file/root/approvedChecksum）。
- 没有面板按钮：先稳定格式，UI 留给同步阶段。
