# 默认开启与真实模型隔离验收

日期：2026-11-15。当前候选：1.0.0-rc.19。状态：准备完成，未正式发布。

## 默认值与日常配置

按所有者最新要求，代码默认 autoSummarize=true，enableUserScope=true。用户显式 false 仍生效；minimal 档仍不执行自动总结。standard/full 档自动总结仍受最少轮数、字符数及闲置时间门槛约束。自动总结会使用宿主模型产生用量，备份默认值不变。

只读核查日常 desktop 配置：autoSummarize 已显式开启，enableUserScope 未覆盖默认值，因此实际也是开启。此前“默认关闭”说的是 rc.18 及更早代码默认值，并非日常配置被关闭。本次没有改日常配置或记忆。

## 真实模型验证

模型：deepseek-account / deepseek-flash，通过本机 DSH 0.2.2-rc.3 实际模型适配器调用。只发送四组虚构事实，使用当前隔离安装的 rc.19 包，自动总结路径不显式设置这两个开关，从而同时验证新的默认开启行为。测试将总结轮数/字符门槛调低、关闭自动合并，以隔离验证分层功能，不代表测试了默认 60 分钟定时等待。

| 类型 | 同项目新会话准确召回 | 其他项目得到的简短概括 | 项目专属细节是否带出 |
|---|---|---|---|
| user | 配色方案 U_VIOLET_731 | 先看图表再听解释的偏好 | 未带出；回答 unknown |
| feedback | 证据编号 F_AMBER_482 | 先列验证证据再下结论 | 未带出；回答 unknown |

| reference | 手册定位符 R_JADE_857 | 有车辆控制调试手册这个资源 | 未带出；回答 unknown |

真实模型为四种类型分别生成项目级详情和同类型用户级概括。新会话的记忆索引由实际宿主 prompt 服务组装；模型根据索引选择读取对象，测试调度器调用真正的 memory_read，再把读取结果交给模型回答。每个召回场景四条记录均成功读取：同项目选择 project 详情，其他项目选择 user 概括。各请求只含当前会话的记忆索引与读取结果，不包含先前会话历史或预期标记答案。

成功验证路径包含 4 次真实自动总结，以及 4 次召回请求（两个场景各一次选择、一次回答）。含排错的请求尝试共 16 次；未采集可靠 token/金额统计，不能据此估算费用。

## 排错记录与证据边界

未把第一次结果冒称为全部通过：第一次总结四类均通过，召回测试脚本错误地把对象传给 createSystemMessage（实际要求字符串），导致记忆上下文未正确传入；另一次轮询遇到短暂写锁，后加入重试。修复系统消息后，模型按索引链接输出了带 .md 的名字，且回答混淆类型归类；测试随后补齐实际 memory_read 的 kebab-case 参数约定与明确的四类问题映射，再复用第一轮已经成功生成的隔离记忆验证召回。没有手工改写模型生成的记忆来通过断言。attempt-1 至 attempt-4 和最终结果均保留。

这是有明确任务和结构化回答约定的真实模型集成测试，不等于任意自然对话均保证正确，也不是完整桌面 UI/自主代理循环端到端测试。模型输出仍可能遗漏、误分类或误概括。凭据只在内存使用现有账号记录，不复制到证据或发布包；日常凭据文件字节前后不变。所有记忆写入都在合成隔离根。本轮按所有者要求不做 VM 测试。
