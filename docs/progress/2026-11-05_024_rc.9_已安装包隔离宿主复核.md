## 发现的缺陷：审计与快照版本字面量未随 rc.9 更新

`src/audit-log.ts:88`、`src/maintenance.ts:136`、`src/storage-safety.ts:182` 都把 `pluginVersion` 写成常量 `'0.1.0-rc.8'`。rc.9 只改了客户端布局和文档，没有同步这三处，因此：

- rc.9 运行时新写入的 `render_attempt` 记录 `pluginVersion` 为 `0.1.0-rc.8`，与 `package.json` 的 `0.1.0-rc.9` 不一致；两组探针（复用 profile 与全新合成根）都复现，证据 JSON 中记为 `auditedPluginVersion: "0.1.0-rc.8"`。
- 备份快照的 `pluginVersion` 字段同理，本轮未单独生成快照验证，但源码路径相同。
- 影响限于版本溯源：审计/快照会声称来自 rc.8，检索和发行证据（如 T20 的组装审计）无法凭版本字段区分 rc.8 与 rc.9。不是安全或数据完整性问题。
- 建议在**下一个候选**里把版本集中为单一来源（构建时注入 `package.json` 版本，或运行时读取自身包元数据），并加一条断言测试；不建议就地重打同版本 rc.9，因为会改变 r78 已记录的包指纹、安装版本和审计基线。是否作为 rc.10 处理需所有者决定。

为复核 rc.9，本轮扩展了 [host-audit-bridge-probe.cjs](../../scripts/verification/host-audit-bridge-probe.cjs)：新增 `--rc9` 分支、证据目录 `S05-rc9-audit-bridge`；把“审计文件必须从零开始”改为按已有行数基线等待新增行（复用 profile 时历史事件保留）；把 `pluginVersion` 断言改为记录实际值并匹配 rc 格式，避免版本缺陷直接中断其余检查。产品代码、rc.9 包和日常配置均未改。
