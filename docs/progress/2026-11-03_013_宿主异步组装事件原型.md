# S05 宿主异步组装事件原型（r08）

日期：2026-11-03。状态：partial。本轮只新增本机宿主探针和证据；生产 WH 插件、数据格式及候选包未改变。

## 已证实

使用本机实际打包的 Cordis 与 @deepseek-ai/dsh-system-prompt 0.2.1-rc.5，在合成 Context 注册一个同步返回空串的 section，再用 `system-prompt/assemble` 异步 waterfall 替换该段。探针断言：

1. 段落回调先同步返回空文本，waterfall 可 await 后替换；最终 `renderPrompt` 输出替换后的文字。
2. 第二次组装读取更改后的合成值；替换逻辑每次组装都会执行。
3. 两次并行组装携带不同 context 值时，返回结果没有串值。

[完整探针结果](../attachments/public-validation.md)。第一次探针在结束时调用了不存在的 `ctx.dispose()`，检查主体已通过但进程退出失败；改用官方 Context 的 `ctx.fiber.dispose()` 后重新运行，进程退出码为 0。失败日志保留在同一证据目录的 stderr 文件，最终探针日志已重写。

## 能做什么、尚不能说明什么

这表明 r07 所否定的“异步 text 回调”之外，**异步组装事件确实是本机宿主可用的候选入口**。生产插件仍未改用它。探针没有加载 WH 插件，没有对 2000 条真实组装跑基准，没有触发模型请求，也未模拟写入期间的文件替换、会话取消和宿主其他插件的完整覆盖段。

尤其要保证审核逻辑从当前源文件重新判断、完整 UTF-8 预算、项目隔离、每次 render_attempt 审计和卸载时监听器清理。异步 scan 原型只证明合成目录可完整读取，尚未证明与当前 sync scan 的锁/格式/竞态语义等价。

## 下一个实现门槛

先在隔离测试中实现异步扫描的等价接口，加入外部语义修改、文件身份变化、根格式和锁冲突、项目同名记录、取消/并行组装等对抗性用例。然后接入 waterfall，核对最终文本和审计只产生一次完整尝试。只有这些通过，才能重新打包并用 wh-s05 做实际宿主升级验收。当前 G4 和大库性能门槛仍开放。
