# S05 · v0.5.0 任务型记忆与可选宿主调度桥接（r140）

- 日期：2026-11-07
- 范围：v0.5.0 开发线（M1 + M2），未切版、未构建候选
- 前序：[r139 桌面升级](2026-11-07_013_日常桌面升级.md) → 本阶段

## 1. 动机与决定

v0.5.0 的核心是“让记忆在合适的时间主动出现”。先做了宿主 `dsh-schedule` 能力探测，确认：

- 宿主有完整的可编程调度服务（Cordis 服务名 `schedule`，`create/edit/list/view/history/run`）；
- 它只搭载在 `dsh-web-app` 组合里，且没有任何公开 `.d.ts`——属于内部契约，不能强依赖；
- 插件的 `ctx.get('schedule', false)` 可拿到服务，缺失时返回 `undefined`。

据此在三条路线里选了**方案 C（混合）**，用户确认（2026-11-07）：

- 记忆文件是**唯一真源**（审核、备份、同步、版本化都留在现有链路）；
- 宿主 `schedule` 只作为**可选投递通道**，缺失/报错时降级为“会话启动注入提醒”；
- 只操作带本插件标记的调度，不碰用户自建任务。

M1（任务字段 + 注入 + 面板 + 同步）与 M2（桥接 + 对账 + 降级）都在本轮落地。

## 2. 实现

### 2.1 数据层

- `src/types.ts`：`MemoryType` 增加 `task`；`TaskStatus = open | done | cancelled`；`MemoryRecord` 增加 `dueAt`（截止，epoch ms）、`remindAt`（提醒时点，缺省用 `dueAt`）、`priority`（1–5，缺省 3）、`taskStatus`（缺省 open，与审核 `status` 正交）。
- `src/store.ts`：解析/序列化白名单加四字段；写入时继承旧值，`clearTaskFields` 显式清空；非 task 记录**强制丢弃**任务字段；dueAt/remindAt 必须是正安全整数、priority 1–5、taskStatus 三值；`reviewFingerprint` 不含任务字段（改期不会把已审核记录打回候选）；任务不进 `MEMORY.md` 索引。
- `src/tasks.ts`（新）：纯函数模块——字段校验/归一、`taskBucket`（overdue/due/soon/later/none）、`collectTaskReminders`（只收 verified+open+未停用，按桶→时间→优先级→名字排序，上限 10）、`TaskReminderTracker`（每会话按签名去重）、`humanizeDuration`。

### 2.2 注入

- `src/injection.ts`：新增 `renderTaskReminderText` 与策略行；输出独立 `<memory_tasks>` 段，声明“不是用户指令”；长期事实索引循环跳过 task。
- `src/index.ts`：新增 `memory-wh:tasks` 段（order 4001），每次组装读取 user + 当前项目两层记录并去重；段渲染失败只清空该段，绝不阻断对话。

### 2.3 面板

- 类型筛选与编辑器加入 task；任务行显示状态、优先级、截止、提醒，并提示“只有已审核且进行中的任务会提醒”；
- 编辑器提供截止/提醒（`datetime-local`）、优先级、状态控件，保存时转 epoch ms、清空发送 `null`；
- 一键“标记完成/取消任务/重新打开”走 `memory.patch`（带 `expectedRevision`）；
- “存储与审计状态”显示宿主调度是否连接及桥接数量。

### 2.4 同步与导入导出

- `SyncRecord` / `ExportRecord` 增加四个任务字段（加法式扩展，旧端忽略）；
- `sameContent` 计入任务字段（只改期也会被识别为变化）；
- 非 task 记录携带任务字段在 `verifyChangeset` / `verifyExportPackage` 阶段直接拒绝；
- 导入/同步落地时展开任务字段；自动固化（`consolidate`）拒绝生成 task（任务必须由用户/面板显式创建）。

### 2.5 宿主调度桥接（M2）

`src/schedule-bridge.ts`：

- `createScheduleBridge({ getService, root, ... })`：`reconcile(records)` 读取真源、逐任务 create/update/delete；
- sidecar `schedule-bridge.json`（`name → { scheduleId, signature, syncedAt }`，tmp+rename 原子写）；
- 幂等：签名（name/title/description/priority/remindAt/dueAt）不变不重复调用；
- 自愈：宿主报 `schedule_not_found` 时重建；`schedule_conflict` 保留 sidecar 并上报冲突；
- 降级：服务缺失或抛错时整体 `skipped`，任务照常进面板与到期注入；
- 孤儿清理：只删“标题以 `记忆提醒：` 开头且正文含 `[memory-wh] task=`”且不在映射里的任务；
- 投递：未来时点用 `{kind:'at'}`，已过期用 `{kind:'after', after_seconds:60}`；目标 `new_once`；标题截 120 字符；正文只放名称+描述（不放完整正文）。
- `src/index.ts`：加载后 10s 首次对账、每 5 分钟一次、会话创建时（60s 节流）补一次；`scheduleStatus` 传给 API。

## 4. 边界与已知未实现

- 桥接用的是宿主内部契约（无 `.d.ts`），宿主升级可能改名/改签名；代码用窄接口 + 整体降级隔离，坏了只关投递通道。
- 真实宿主投递（新建会话看到 `[SCHEDULE REMINDER]`、关掉 DSH 再重开补投）尚未在真实 desktop 上验证——需要 0.5.0 候选安装后做一次端到端演练，并保留证据。
- 宿主 `schedule.json` 不在记忆树内：不进 WH 备份、不参与同步；卸载插件后可能留下孤儿（有标记，可人工清理；本轮未加 `memory-cli` 清理命令）。
- “可静音”目前用 `disabled: true`（不提醒、保留记录）；批量完成/取消未做；里程碑触发（5.4 第 4 项）未做。
- 宿主侧若被用户在调度页改动，下一次对账以记忆为准覆盖（`schedule_conflict` 只上报不覆盖），未做交互式“以哪边为准”。
- 至少 1 个月真实提醒运行属于发布前验收，不在本轮。
