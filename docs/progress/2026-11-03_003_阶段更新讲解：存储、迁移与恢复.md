## 1. 这一阶段解决什么问题

S02 已把 WH 身份和默认数据根分开，但继承的删除仍直接移除文件，中断写入缺少恢复记录，旧库也没有明确的复制迁移流程。S03 建立可检查、可恢复的存储基础。

例如，删除一条记忆后，现在能从归档恢复其原始字节；恢复前发现同名新记录则拒绝覆盖。迁移前的计划记住源清单，源文件后来变化就必须重新制定计划。备份不只检查“文件存在”，还会在另一目录恢复并核对字节。

## 3. 改动讲解

**事务与锁。** 每次修改取得 WH 根写锁和作用域索引锁，在改变活动记录前持久保存原状态。普通异常尽力回退；若恢复本身失败，留下日志并阻断未确认数据的读取。事务中的 Prompt 索引返回空段，避免把中间状态发送给模型。为避免误删活跃锁，取消自动清理疑似孤儿锁，改为停写后核验 PID 与锁哈希的显式维护。

**删除和批量修改。** 原来的 unlink 删除改为先保存归档再移除活动文件，索引在同一作用域事务内更新。批量清空和修剪先生成独立快照；修剪在锁内重新计算年龄。恢复归档保留正文、信任和关系的原始字节，且不覆盖后来新建的同名记录。跨作用域批量请求仍由各自事务组成，不承诺跨两层原子提交。

**旧库迁移。** 已有非空、无 WH 标记的根拒绝写入。计划盘点所有相关文件，报告坏文件、未知文件/版本/信任状态、目录链接和映射缺失。执行还会重新检查当前异常与清单，不仅相信计划中的声明。源、目标与备份必须互不包含，目标必须全新。迁移只准备独立副本，保留旧源，并不切换 DSH。

**元数据和项目身份。** 迁移和归档保留原始文件字节。普通记录更新保留未知顶层 frontmatter 字段。上游项目 slug 可能碰撞，因此新增完整路径绑定；两个不同路径不能静默共用同一项目目录。迁移旧目录需要操作者提供/确认原路径映射。

**并发编辑。** 存储层读取返回 revision，传入 expectedRevision 的编辑在锁内核验；过时编辑被拒绝。旧 UI/API/模型工具尚未全部强制使用该字段，所以不声称所有同名覆盖问题都已解决。

- **中优先级：** 归档/快照/日志未加密，不能视为隐私擦除；未实现自动保留策略、永久清理或云同步。
- **中优先级：** 用已停止写入者加合作文件锁保证维护一致性；不能强制约束外部编辑器、旧插件或同权限恶意进程。
- **中优先级：** SHA-256 用于完整性比对，不能证明备份来源或签名。宿主 build commit 也只是本机包内元数据。
- **中优先级：** 文件限额、全作用域快照开销及 Windows 目录刷写限制必须在实际部署前评估；不承诺物理断电零丢失。
