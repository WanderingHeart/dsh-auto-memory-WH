# r143 — v0.5.0 真实宿主投递核对 + 任务完成即归档

- 日期：2026-11-07
- 阶段：S05 / v0.5.0 开发线（真实宿主 e2e 与完成语义）
- 前置：r142（桌面已升级到 0.5.0，重启后生效）
- 结论：方案 C 的 M2 在真实桌面**端到端成立**；同时把“任务完成”改为归档删除。

## 1. 核对方法

用户重启 DSH 后（GUI `51685`），要求在 1 分钟后提醒吃饭。由于会话内没有 `memory_write` 工具，
用 Node 的类型剥离直接调用存储层写入一条 `type: task` 的 user scope 记忆：

```powershell
node --experimental-strip-types .work/create-eat-reminder.mjs
```

任务字段：`dueAt = remindAt = 创建时刻 + 90s`、`priority: 1`、`taskStatus: open`、`status: verified`。
随后观察三处证据：`~/.dsh/storages/schedule.json`、`~/.dsh/memory-wh/schedule-bridge.json`、
以及 `~/.dsh/sessions` 下的会话记录（zstd 压缩，用 `zlib.zstdDecompressSync` 解开后检索）。

## 2. 观察结果（详见 `docs/evidence/S05-v050-tasks/host-delivery.json`）

1. **桥接创建宿主任务**：`schedule-2f008aa7-367d-4692-b3e3-99cdfb102f2b`，标题 `记忆提醒：去吃饭`，
   prompt 带 `[memory-wh] task=eat-now-reminder` 标记，target 为 `new_once`。
2. **到点投递**：19:27:09.831 新建会话 `session-a7926db8…`，19:27:09.926 投递
   `[SCHEDULE REMINDER]`（`source.kind = schedule`），19:27:16.068 该会话的 agent 回复提醒吃饭。
   会话标题就是 `记忆提醒：去吃饭`。
3. **完成即清理**：用户在面板标记完成后，19:46:09.843 收到 `[SCHEDULE CHANGE] change: deleted`；
   `schedule.json` 的 `tasks` 变为空，sidecar 的 `entries` 也为空。

也就是说：**创建 → 到点投递到新会话 → 完成后删除宿主任务**，三条链路都在真实宿主上走通；
上一轮 r140 里“真实宿主投递未验证”的边界到此关闭。

## 3. 行为调整：完成即归档删除

用户反馈“任务记忆在标记完成后就直接删除吧，更符合日常使用”。实现为：

- `src/tasks.ts` 新增 `isCompletedTask(record)`：`type === 'task' && taskStatus === 'done'`。
- `src/memory-tools.ts`：`memory_write` 写入后若任务已完成，立即
  `store.deleteVersioned(...)`，返回 `operation: 'deleted'`。
- `src/management-api.ts`：`memory.write` / `memory.patch` 在写入结果为已完成任务时同样归档删除，
  返回 `{ ok: true, deleted: true, archive }`。
- 删除走**版本化归档**而不是直接 unlink：面板的归档里可恢复，同步端会收到墓碑，
  不会在别的设备上复活；宿主侧调度在下次对账时按“记忆里已不存在”删除。

测试同步更新：`tests/task-memory.spec.ts` 增加“工具标记完成后读取报 NOT_FOUND”，
API 用例改为断言 `deleted: true` 且列表不再包含该任务。全量 `43 文件 / 440 用例` 通过。

## 5. 边界与未做

- 这是单机观察；跨设备任务同步只有单测覆盖，未做双机演练。
- 关掉 DSH 期间不会投递，重启后只补最近一次错过的时点（`dsh-schedule` 语义）。
- 投递至少一次，可能重复；不会丢。
- sidecar 丢失最多造成一次重复创建，不会丢任务。
- `schedule.json` 不在记忆树内，不参与 WH 备份。
- 已完成任务的删除是“归档”，面板归档页仍可恢复；如果希望连归档也不保留，需要另开选项。
