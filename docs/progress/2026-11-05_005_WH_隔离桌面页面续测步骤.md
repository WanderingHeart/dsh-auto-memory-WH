# WH 隔离桌面页面续测步骤

日期：2026-11-05。对象：DSH Desktop `0.2.1-rc.5` nightly、WH 本地包 `0.1.0-rc.8`，只使用项目 `.work/S05/native-real-user-home` 和合成记忆。**本轮已按下列步骤完成隔离原生页面只读验收与卸载；命令保留供历史复核，不要在现有 profile 上直接重跑。** 结果见[r66](2026-11-05_011_rc.8_原生桌面合成记录验收.md)。

## 为什么可以不输入账号或密钥

对当前 `app.asar` 固定 SHA-256 的只读检查显示：欢迎页的“添加 API Key”视图提供“稍后配置”按钮，其官方 IPC `skip` 会调用进入工作区的路径；登录/密钥均未配置时，欢迎页才会出现。[静态契约结果](../attachments/public-validation.md)。这只是代码路径证据，**尚未证明本机离线点击和 WH 页面实际可用**。不修改 DSH 程序、账户或安全设置，也不通过注入脚本绕过登录。

## 已准备的隔离现场

- 首次卸载后 profile 的五个配置/锁文件备份固定在 `.work/S05/native-desktop-profile-postremove-r65/`，安装脚本的 `-PostRemoveBaseline` 只接受这些固定哈希；正常 Windows 账户的只读 `Check` 已返回 `ready-for-isolated-desktop-reinstall`。不使用 PATH 上的旧全局 CLI。
- 项目 `.work/S05/native-real-user-home/memory-wh` 已写入唯一的合成用户级记录 `native-ui-synthetic`，核对结果见[种子记录](../attachments/public-validation.md)。它不代表用户事实或偏好，不读取真实记忆。
- [续启工具](../../scripts/verification/native-desktop-wh-resume.ps1)默认只检查：固定原版 exe/asar、WH 包、空白测试凭据指纹、正常非管理员用户、项目内四个隔离目录、已安装 WH rc.8、零 DSH 进程。显式 `-Action Launch -OfflineConfirmed` 才启动原生 GUI；它把包含临时 localhost token 的控制台输出写在项目 `.work/S05/native-wh-ui-log-*/`，不打印到终端。日志可能包含临时访问令牌，**不要直接上传或截图日志**。

## 用户离线操作

在普通 PowerShell 窗口执行，不要以管理员身份运行。先保存工作、正常退出所有 DSH 窗口，并确保任务管理器里没有 `DeepSeek Harness` 进程。断开电脑的互联网连接后，依序运行：

1. 再次安装固定本地包：

   ```powershell
   & "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-plugin.ps1" -Action Install -PostRemoveBaseline -OfflineConfirmed
   ```

   只有结果包含 `installed-in-isolated-desktop-profile` 才继续。

2. 只读检查续启条件：

   ```powershell
   & "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-wh-resume.ps1" -Action Check
   ```

   只有结果包含 `ready-for-isolated-wh-desktop-launch` 才继续。

3. 启动隔离原生窗口：

   ```powershell
   & "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-wh-resume.ps1" -Action Launch -OfflineConfirmed
   ```

   只有结果包含 `isolated-wh-desktop-launched-not-yet-accepted` 且原生窗口打开，才在窗口中继续。若看到“登录未完成”，点击“添加 API Key”，在下一页点击“稍后配置”；**不要输入任何真实或测试密钥，也不要点击重新登录**。若进入工作区，寻找“记忆 WH”，检查是否出现合成记录 `native-ui-synthetic`。只查看页面，不发送消息或修改记忆。截图只拍 DSH 窗口，避免包含本机访问 token。

4. 正常退出 DSH，确认没有 DSH 进程。若前面都成功，再运行官方 CLI 卸载：

   ```powershell
   & "C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe" -NoProfile -File "C:\Users\example-user\Desktop\dsh-plug-in\dsh-auto-memory-WH\scripts\verification\native-desktop-plugin.ps1" -Action Remove -OfflineConfirmed
   ```

   只有结果包含 `removed-from-isolated-desktop-profile` 才算本次功能性卸载成功。之后恢复网络，把安装、检查、启动、卸载四段**状态输出**及 DSH 窗口截图发回；不要发送 `.work` 日志原文。

任一步报错、界面不符、程序崩溃或出现权限/更新提示，就停止后续步骤，正常退出能退出的窗口，保留现场，恢复网络后报告观察结果。不要重复安装、手工删除文件、改 DSH 安装目录权限或把测试目录指向日常记忆。`-OfflineConfirmed` 只记录人工断网，未经独立测量不能声称所有出站请求都留在本机。
