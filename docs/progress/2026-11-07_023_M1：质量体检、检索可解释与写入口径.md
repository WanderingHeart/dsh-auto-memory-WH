# v0.6.0 M1：质量体检、检索可解释与写入口径（r149）

- 日期：2026-11-07
- 目标版本：v0.6.0（开发线，未切版）
- 关联：roadmap 1.8 / 5.5、`docs/attachments/memory-quality.md`

## 1. 动机

v0.5.2 解决了“任务一变就对账”，但记忆本身的质量仍只能靠人工抽查。roadmap 1.8 要求“写得准、找得到、不过期、不臃肿”，并把规则分层、写入口径、检索召回、去重、索引预算与度量列为七个方向。本轮先把**可观测**与**可解释**做出来：不改变存储与信任语义，只增加只读体检和召回原因。

## 2. 实现

### 2.1 质量体检（`src/quality.ts`）

- 纯函数 `lintRecord(record, nowMs)` 按记录逐项判定 8 类问题：
  - `title-missing`、`description-long`（>240 字符）、`body-short`（<40 字符）、`name-generic`（`memo/notes/todo/temp/...`）、`task-missing-due`、`task-overdue`（逾期 >7 天）、`verified-stale`（180 天未更新且未 pinned）、`body-many-sections`（>4 个二级标题）。
- 任务记录特殊处理：已完成/取消不提示截止与逾期；任务不参与“正文过短/多标题”；superseded 不提示正文过短；candidate 不提示 stale。
- `qualityReport(records, nowMs, limit=100)` 汇总 `scanned/flagged/byCode/records/thresholds`，warn 优先、按名称稳定排序，`limit` 只截断列表并保留总数。

### 2.2 只读 API 与面板

- `management-api.ts` 新增 `quality.report`（POST，空参数，scope 从 common 参数取），直接返回 `qualityReport(await store.list(scope, cwd), Date.now())`；不写任何记录。
- 管理面板工具栏在“运行指标”后增加“质量体检”按钮，结果渲染在 `<section aria-label="记忆质量体检">`：扫描/标记数、阈值说明、逐条问题与建议；切换 scope 时清空旧结果。

### 2.3 检索可解释

- `memory_search` 每条命中新增 `matchedIn: string[]`：记录命中落在 `name`/`title`/`description`/`body` 的哪些位置（description 另由 `descriptionCoverage` 打分）。输出 schema 同步新增该字段。

### 2.4 索引占用（M2 第一步）

- `quality.report` 可选返回 `index: { bytes, budget, excluded }`：宿主在 `src/index.ts` 注入 `indexUsage` 回调，调用 `renderMemoryIndexDetailAsync(store, config, cwd)` 取真实渲染字节与排除原因；回调缺失或抛错时省略该字段，体检本身不受影响。
- 面板显示“索引占用 X / Y 字节”，超预算时提示“注入会被截断”，并给出被排除条数。
- 这让“索引预算”从只能看审计日志变成体检页上的直接数字，也是 5.5 第 5 项的观测基础。

### 2.5 写入口径文档

- 新建 `docs/attachments/memory-quality.md`：三层规则分层表、一条一决策、什么不值得写、何时写、八类体检项与建议、检索与召回、索引预算、复查节奏、度量基线清单。

### 2.6 autoSummarize 价值门槛（M2）

- `src/quality.ts` 导出 `isGenericName(name)`（复用小写/空白归一后的通用名单）。
- `applyConsolidationCandidates` 的 create 分支在 `minImportance`/`isChitchat`/去重之后再加一道门槛：候选名是 `notes/todo/misc` 之类通用名时直接丢弃，记入 `tally.lowQuality` 并写日志。理由：通用名既不可检索，也无法被后续更新/合并稳定锚定；宁可不写，让模型下一轮用有信息量的名字重试。
- update/supersede 分支不受影响——已有记录的名字是既定锚点。

### 2.7 索引排除明细与度量基线（M2）

- 体检页在“N 条被排除”下增加可展开明细（记录 id + 原因），并说明“被排除的记录仍完整保存在磁盘上，只是不进入索引”。
- 体检返回 `duplicates: {groups, threshold}`（复用 `findNearDuplicateGroups`，阈值 0.8），面板显示“近重复 N 组：用上方查找近重复逐组查看，再归档或改写；流程不会自动合并”，把“发现”和治理入口串起来。
- 新增 `scripts/verification/quality-baseline.mjs`：只读扫描真实记忆根（默认 `~/.dsh/memory-wh`），统计记录数、按 scope/type/status 分布、体检 flagged/byCode、近重复组数、索引字节/预算/排除数，写入 `docs/evidence/S05-v060-quality/baseline.json`。
- 首次基线（2026-11-07）：19 条（全部 user scope），reference 10 / user 5 / project 4；verified 16、superseded 2、candidate 1；flagged 5（`title-missing` 4、`body-many-sections` 1）；近重复 1 组；索引 3558 / 4096 字节，排除 3 条。

### 2.8 面板分页/滚动与投递工作区（M2 补充）

- 面板每页 5 条（`PAGE_SIZE`，原 25），翻页、页码、“每页 N 条”文案统一。
- 刷新不再清空列表：只有“范围/会话/查询/状态/类型/页码”变化才 `setData(null)`；定时刷新与手动刷新保留旧列表，只是把数据换成新的。否则列表卸载、页面变矮，浏览器会把滚动位置夹回顶部。加载提示也只在首屏出现，避免刷新时插入一行把内容顶下去。
- 宿主投递工作区：项目任务创建 `new_once` 时带 `create.cwd`（任务所属项目目录），新会话因此归到该工作区而不是 profile 目录（`未分组`）；user 任务不带 cwd，保持宿主默认。`schedule-bridge.json` 的每条映射记录 `cwd`；工作区变化时删除旧宿主任务并重建（宿主不允许原地改 target）。
- 新增测试：桥接 3 例（user 任务不带 cwd、项目任务带 cwd 且 sidecar 记录、cwd 变化时重建）、面板 2 例（每页 5 条与翻页 offset、刷新期间列表保持挂载）。

## 4. 边界与未覆盖

- 体检是启发式规则，不知道记录的真实重要性；`pinned` 只跳过 stale，不代表内容正确。
- 未做自动修复或批量改写：所有建议都要求人工确认，避免“自动美化”掩盖信息丢失。
- 通用名门槛只作用于自动固化的 create 分支；人工写入、同步导入不受限（由体检提示）。
- 真实一周对比未完成：目前只有单点基线，无法判断趋势；需 2026-11-08 前后再采一次同口径数据。
- 未切版：`package.json`/`lib/` 仍为 0.5.2。

## 5. 下一步

1. 近重复治理流程：把“查找近重复 → 合并建议 → 人工确认 → 可恢复”串成面板上的固定路径，并在体检里给入口。
2. 索引预算排序治理：验证 pinned/importance/描述长度在预算紧张时的保留顺序是否符合预期（必要时补“近期使用”加权）。
3. 一周后复采基线（同一脚本），对比 flagged 比例、近重复组数、索引占用趋势，再决定是否切 0.6.0。
