# S05 / v0.12.4 — 总结浮层互斥、路由兜底与空状态诊断

- 日期：2026-11-08
- 版本：0.12.4（`1.0.0-rc` 线准备中）
- 候选包：`.work/dsh-auto-memory-wh-0.12.4.tgz`（179,408 字节，
  `15c55099…e4e`）
- 结论：隔离 `wh-s05` 22/22，真实桌面升级 7/7。

## 1. 起因

0.12.3 交付后，所有者重启 DSH 实测发现三个问题：

1. 点工具栏其它按钮或空白处时，“总结”浮层不收起；
2. 同时打开“档位”和“总结”时两个浮层左右重叠；
3. “总结”浮层显示“没有可总结的活跃会话”，而当前会话仍在进行。

## 2. 修复

### 2.1 浮层互斥（`src/client/ManagementPage.tsx`）

原来的全局 `mousedown` 处理器只认 `filterRef` 与 `editionRef`，总结浮层既不在
关闭列表里，也没有任何“同一时间只开一个”的约束。现在处理器遍历
`details.dam-wh-filter[open]`：凡不包含点击目标的 details 一律收起，并同步
`setFilterOpen/setEditionOpen/setSummaryOpen`。点浮层内部不关闭。

### 2.2 路由兜底（`src/consolidate.ts`）

`recent()` 只返回“拿得到 provider/model 路由”的会话，而路由原先只在
`agent/created` 记录。插件晚于宿主恢复会话加载时（桌面重启、切换工作区），
这条事件已经错过，于是出现“有缓冲、无路由、列表为空”。

新增 `liveAgentRoute(sessionId)`：从宿主注册表
`ctx.agents.get(sessionId)` 取 `agent.options.provider/model` 与
`effectiveProjectCwd`，写回路由缓存。`resolveRoute` = 缓存优先、注册表兜底，
`fireIdle`、`scheduleIdle`、`agent/disposed`、`recent`、`summarize` 全部改用它。

### 2.3 空状态诊断（`src/consolidate.ts` + 面板）

新增 `ConsolidationDiagnostics { captures, routes, agents, autoSummarize }`，
`consolidation.sessions` 随 `sessions` 一起返回。空状态显示
“本进程捕获 N 个会话、M 个有模型路由、K 个活跃代理”，把“没有缓冲”“没有路由”
“没有活跃会话”区分开，避免下次只能靠猜。

## 4. 边界

- 诊断计数是进程内的，重启归零；不包含正文，不写入审计。
- 兜底只补 provider/model/cwd；拿不到路由的会话仍不会出现在列表里。
- 宿主注册表 API 是可选读取（`ctx.agents` 不存在时视为无路由），不影响旧宿主。
