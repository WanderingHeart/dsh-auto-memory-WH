# S05 子代理当前目录与记忆范围修复（r23）

日期：2026-11-03。状态：**partial**。本轮修复在真实 DSH spawn/fork 子代理路径中发现的项目范围错误。代码仍为工作树构建；`wh-s05` 隔离配置内已安装的 rc.2 包未升级，日常 DSH 未改动。

## 问题与修复

DSH 0.2.1-rc.5 创建子代理时，孩子的会话头保留父会话最初的 `cwd`，随后 `dsh-working-directory` 以 `working-directory/change` 事件提交孩子的**当前工作目录**。已安装 WH rc.2 从会话头取项目范围，导致 spawn 到另一个合成项目时仍注入父项目记忆。[旧包基线](../attachments/public-validation.md) 在明确的隔离断言处失败，输入中含父项目记录 `parent-reviewed`。

修复后的 WH 从宿主当前目录服务读取项目范围，供提示词注入、五个记忆工具、管理页会话映射及自动固化使用。服务存在但返回无效目录或报错时拒绝项目范围；仅在没有目录服务的旧组合中回退到会话头。目录切换时清除自动固化的旧项目缓冲，避免跨项目混合。变更见 [目录边界](../../src/project-context.ts)、[主插件](../../src/index.ts)、[记忆工具](../../src/memory-tools.ts)、[固化](../../src/consolidate.ts) 和 [回归测试](../../tests/project-context.spec.ts)。存储格式未变，不涉及迁移。

## 隔离验收

[宿主探针](../../scripts/verification/host-subagent-routing-probe.cjs) 使用打包 DSH 的真实 agent loop、spawn/fork provider、会话持久化和 working-directory 服务；文件系统与模型调用由合成替身提供，所有项目目录位于 `.work/S05`。修复后的本地构建通过：[结果](../attachments/public-validation.md)。

- spawn 孩子的会话头仍指向父项目，但宿主当前目录为新项目；WH 不注入父项目记忆。fork 保留父项目目录与已完成的父会话前缀，仍可注入父项目记忆。
- spawn 的项目记忆工具可写、读自己的候选记录；父 agent 读同名记录返回 `NOT_FOUND`。
- 两个孩子经本地假模型完成回合，模型调用 **2 次**，拦截到的网络请求 **0 次**。WH 记录 **5 条**组装审计：父与 fork 的 3 条含已审核记忆，spawn 的 2 条为零字节。
- 类型检查、构建及完整回归通过，**271/271**：[typecheck](../attachments/public-validation.md)、[build](../attachments/public-validation.md)、[tests](../attachments/public-validation.md)。
