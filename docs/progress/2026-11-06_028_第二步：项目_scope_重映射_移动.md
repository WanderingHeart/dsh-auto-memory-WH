# r125 — v0.3.0 第二步：项目 scope 重映射/移动

- 时间：2026-11-06 23:55（Asia/Shanghai）
- 阶段：S05 / v0.3.0 开发线
- 状态：重映射完成；合并/归档/主题合并未开始
- 关联：`docs/attachments/roadmap.md` 5.2 第 1 项

## 1. 背景

项目 scope 的目录名由 `projectKey(cwd)` 决定。项目目录改名、工作区移动或换机后，`.wh-project.json` 里的 cwd 会与目录名、会话 cwd 不一致；过去只能人工改标记或删库重来。

## 2. 实现

- `src/projects.ts` 新增 `remapProject({root, fromCwd?, fromDirectory?, toCwd, writersStopped})`：
  - 必须显式 `writersStopped: true`；
  - `toCwd` 必须是绝对路径；
  - 源目录必须存在且标记合法；给出 `fromCwd` 时会核对标记里的 cwd，不一致直接拒绝；
  - 目标 cwd 与当前 cwd 相同 → 拒绝（`already mapped`）；
  - 目标目录已存在（另一个 cwd 或另一个 scope）→ 拒绝（`Project directory collision`），不做隐式合并；
  - 通过 `renameSync` 移动目录，再用临时文件 + rename 原子重写 `.wh-project.json`；
  - 返回 `{fromDirectory, toDirectory, fromCwd, toCwd, records}`，不返回正文。
- `maintenance-cli` 新增 `project-remap` 命令；`docs/storage-recovery.md` 命令表补充 `projects` 与 `project-remap`。

## 3. 验证

- `tests/projects.spec.ts` 增加到 4 项：
  - 改名后目录、标记、记录内容均正确，盘点结果只剩新 cwd；
  - 未停止写入者 → 拒绝；
  - 目标 cwd 与当前相同 → 拒绝；
  - 目标目录已存在 → 拒绝（collision）。
- `typecheck` 通过；目标测试 4/4 通过。

## 4. 边界

- 只做“同一份作用域换 cwd”的重映射，不做两个项目 scope 的合并；
- 不改写历史审计、备份清单或外部 `projectMappings` 中的旧 cwd；
- 不重建 `MEMORY.md`（它由记录派生，下次写入/维护时自然重建）；
- 跨机迁移需要先恢复根目录，再用目标机器上的新 cwd 执行 remap。
