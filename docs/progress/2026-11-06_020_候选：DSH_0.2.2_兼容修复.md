# S05 · 0.1.0 候选：DSH 0.2.2 兼容修复

- 时间：2026-11-06（Asia/Shanghai）
- 状态：候选包重切并完成 21 步隔离验收；日常桌面待所有者关闭 DSH 后执行修复脚本
- 关联：[r114 候选验收](2026-11-06_016_r114_—_0.1.0_定稿候选的_21_步验收入口.md)、[r116 发布就绪](2026-11-06_019_公开发布就绪（未发布）.md)、[发布流程](../attachments/release.md)

## 起因

DSH 桌面自动更新到 **0.2.2-rc.1** 后，日常桌面的“记忆 WH”入口消失。插件文件仍在 profile 中（`bundles` 含 `dsh-auto-memory-wh`、依赖指向 `.work/dsh-auto-memory-wh-0.1.0.tgz`、`node_modules` 内版本 0.1.0），并非被卸载。

## 诊断

`dsh` 启动日志明确给出原因：

```text
dsh: skipping profile bundle "dsh-auto-memory-wh": Error: Plugin dsh-auto-memory-wh@0.1.0 is incompatible with dsh 0.2.2-rc.1:
requirements {"@deepseek-ai/dsh-agent":"0.1.5-rc.2 || 0.2.1-rc.5", ...}
```

- 打包宿主的 `@deepseek-ai/dsh-app-boot` 用 semver（`includePrerelease: true`）对照 `peerDependencies` 中的 `@deepseek-ai/dsh-*` 版本。
- 0.1.0 的 peer 列表只枚举了 `0.1.5-rc.2 || 0.2.1-rc.5`，不含 `0.2.2-rc.1`，于是整个 profile bundle 被跳过，客户端面板自然不出现。
- 该检查支持 `engines.dsh`：声明后**只**用该范围判定，不再逐项比对 peer 列表。

证据：`docs/evidence/S05-0.1.0-dsh022/diagnosis.json`。

## 修复

1. `package.json` 增加：

   ```json
   "engines": { "node": "^22.19.0 || >=24.0.0", "dsh": ">=0.2.1-rc.5 <0.3.0" }
   ```

   保留 peerDependencies 作为“已实测宿主版本”的说明；兼容判定以 `engines.dsh` 为准。
2. **重切 0.1.0 候选**（未发布，版本不变以保持清单/证据一致）：
   - 15 文件、101,738 字节、SHA-256 `356C0DB6409E057A72E348EFC1B30AD5807924991EA7AEDA928E2E76D2AE3193`、shasum `1875c7038939a6009e4c812fe22102dcb77b3f7b`；
   - `lib/index.js` 未变，SHA-256 `2CE1DEEF7DC9BB96876CD857291CE02EB80918ECDC381426D2C59FE259C8C11E`。
3. 验证脚本适配：
   - `host-audit-bridge-probe.cjs` 组合中加载 `@deepseek-ai/dsh-tool-executor-native`（0.2.2 的 `dsh-system-prompt` 组装需要工具执行器，否则 `ToolExecutorUnavailableError`）；
   - `installed-peer-topology.cjs` 优先按 `engines.dsh` 判定兼容，并记录 `hostVersion`/`enginesDsh`/`enginesMatch`；peer 列表仍输出，作为“宿主供给拓扑”的说明。
