## 回退预案（不执行日常回退）

1. 暂缓把候选版装进日常 DSH。正式升级前，在 DSH 完全退出后备份日常 profile（包括清单、锁文件与 patch）、实际配置的 WH 记忆根和旧插件包；把备份和 SHA-256 留在本机，不提交到 Git。原安装若不是 npm 标准包，还要保留现装包本身。
2. 若升级后出现加载失败、读写异常或不预期的配置变更，先停写并退出 DSH，再备份升级后的数据和日志。通过同一 profile 的管理器重新安装已校验的 1.0.1 归档，核对 profile、bundle 及其它依赖没有被意外改动，重启后核对加载版本。
3. 软件回退不等于数据回退。正常情况下保留现有记忆；有数据问题时，先在独立目录恢复并校验旧快照，盘点新旧差异后另行确认切换，绝不覆盖仍需保留的升级后数据。
4. 发布前先比对待发布归档与已验收归档的 SHA-256；发布后先在隔离 profile 从 npm 安装明确版本做冒烟验证，再决定是否升级日常环境。
