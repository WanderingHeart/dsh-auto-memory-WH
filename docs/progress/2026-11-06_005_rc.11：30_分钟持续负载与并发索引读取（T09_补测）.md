# S05 rc.11：30 分钟持续负载与并发索引读取（T09 补测）

- 日期：2026-11-06
- 状态：隔离、合成数据；产品代码未改
- 关联：`docs/progress/2026-11-06_018_发行前门槛清单.md` T09；`scripts/verification/soak-mixed-load.mjs`、`soak-worker.mjs`、`concurrent-index-readers.mjs`
- 证据：`docs/evidence/S05-rc11-soak/result.json`（17/17）、`docs/evidence/S05-rc11-concurrent-readers/result.json`（5/5）

## 起因

T09 的剩余边界写着“多窗口 UI 与数小时级长期运行未关闭”。多窗口 UI 属于原生交互，离线无法补；但“写入负载持续更久”和“写入期间索引读取是否安全”可以离线补。本轮把 r98 的 6 分钟四进程负载延长到 **30 分钟**，并新增四个并发索引读取者。

## 30 分钟持续负载

`node scripts/verification/soak-mixed-load.mjs 30 2 2`，`SOAK_MAX_UNIQUE_WRITES=600`：

| 指标 | 结果 |
|---|---|
| 进程 | 2 个 unique + 2 个 churn，持续 30 分钟 |
| unique 写入 | 235 + 230 = **465** 条，全部存在、无缺口 |
| churn 写入 | 417 + 469 次成功，67 次版本冲突、21 次锁超时，均重试成功 |
| unique 锁超时 | 63 + 60 = **123** 次（每次等满 10s 后重试） |
| 读重试 | 21,827 次 `Storage busy or recovery required` |
| 最终记录 | 466 条（465 unique + soak-churn） |
| 最终索引 | 4064 字节 / 75 条注入（≤4096） |
| 残留 | 无锁、无 journal、无 tmp |
| 采样 | 54 次，16 次读取遇到存储忙；成功采样中 list 最大 761ms、索引 2–3ms |

观察：

- 30 分钟写入总量（465）并不比 r98 的 6 分钟（240）线性增长——每写一次都要 `captureScope` 读全量记录，4 个写者串行抢根锁，锁等待开始主导吞吐；unique 写者在 30 分钟里各遇到 60+ 次 10s 超时。
- 写入期间 `scanSync` 持续 fail-closed：采样到的索引段多为 0 字节，写入停止后立即恢复为 4064 字节；读取方拿到的是“空段 + 忙重试”，不是部分/损坏的索引。
- 数据完整性不受吞吐下降影响：465 条唯一记录零缺口，churn 正文与序号一致，结束后无残留。

## 并发索引读取

`node scripts/verification/concurrent-index-readers.mjs 60`：4 个异步 reader 每 25ms 组装一次索引（maxBytes 4096），同时 2 个 unique + 2 个 churn 写者持续写入 60 秒。

| 指标 | 结果 |
|---|---|
| 渲染次数 | 4649（其中 4575 次为空段，即写入窗口内 fail-closed） |
| 最大段字节 | 4016（≤4096） |
| 非法 UTF-8 / 切断字符 | 0 |
| 抛出异常 | 0 |
| async 与随后的 sync 渲染不同 | 5 次（并发提交落在两次读取之间，属预期；不计失败） |
| 结束后 | 记录 89 条、索引 4016 字节 / 67 条注入、无锁/journal |

说明：早先版本把“async 与 sync 逐字节相同”当硬断言，在并发写者存在时错误地失败（实测 9 次差异）。修正后的断言是“每次渲染要么是合法空段、要么字节与预算一致，且同步/异步各自都满足契约”；两次渲染之间发生提交导致的差异只记录不判失败。

## 结论与边界

- T09 的合成长时间负载从 6 分钟扩到 30 分钟，并补上“写入期间读取索引”的并发窗口；两项均通过，无数据损坏或残留。
- 仍开放：多窗口 UI（需要原生桌面）、数小时级（本轮 30 分钟）、真实设备上的缓存/磁盘行为。
- 吞吐观察值得写入发布说明：持续多写者下保存会以 10s 锁超时 + 重试的方式变慢，单 scope 的记录数继续增长时更明显（r84 的 4096 文件上限是硬边界）。
