# r127 — v0.3.0 跨会话召回排序

- 时间：2026-11-07 00:01（Asia/Shanghai）
- 阶段：S05 / v0.3.0 开发线
- 状态：5.2 第 2 项完成
- 关联：`docs/attachments/roadmap.md` 5.2 第 2 项

## 1. 背景

原有注入排序是“pinned → importance → updatedMs → id”，只看写入时间；读取历史（`lastReadMs`、`reads`）与当前项目上下文没有参与排序。跨会话使用时，最近读过/用过的记录应优先，当前项目 scope 在同分时应优先。

## 2. 实现

- 排序改为复用 `memoryScore(record, now)`（importance × 0.995^天，锚点 `lastReadMs ?? updatedMs ?? createdMs`）：
  - 注入顺序：pinned → `memoryScore` → 项目 scope（仅同分时优先）→ `updatedMs` → id；
  - 预算紧张时的候选排序同样用 `memoryScore` 作为查询相关度之后的次级键。
- `memory_list` 新增可选 `sort`：`updated`（默认，保持原行为）、`relevance`（`memoryScore`）、`name`；非法值返回 `INVALID_INPUT: sort`。
- `memory_search` 在关键词得分相同的情况下，按 `memoryScore` 再按名称排序（关键词得分仍是第一优先级）。

## 3. 验证

- 新增 `tests/recall-order.spec.ts`（3 项）：
  - pinned 永远第一，之后按跨会话时效分排序（120 天未读的 feedback 让位给今天更新的 project）；
  - 同分时项目 scope 先于 user scope；
  - 锚点是 `lastReadMs` 而非写入时间。
- `tests/wh-s04.spec.ts` 增加 1 项：`memory_list` 的 `relevance` 与 `name` 排序、非法 `sort` 拒绝。
- `typecheck` 通过；相关测试 12/12。

## 4. 边界

- 分数按“天”粒度取整，单日内的微小时间差不会改变顺序；
- 没有会话 id 参与排序，所谓“跨会话”指读取/更新时间与项目上下文，而非会话相似度；
- 项目 scope 只在同分时优先，不会压过更高 importance 的 user 记录；
- 注入顺序变化属于行为变更：已审核记录集合不变，只是预算紧张时入选的条目可能不同。
