# r199 — v1.0.0-rc.12 词面增强与合并列表中文标题

日期：2026-11-09（Asia/Shanghai）
目标：在零 token、确定性的前提下，提高自动合并/待确认的相关性命中率，并让合并列表显示用户可读的中文标题，而不是记录名。

## 1. 目标与范围

- 自动合并与“待确认”列表继续复用 `relatedness.ts` 的词面打分，不引入模型或 embedding。
- 词面增强：高置信中英同义词归一到同一词元；名称中的连字符/下划线按子词再切分。
- 合并列表优先显示记录的 `title`，没有 `title` 才回退到 `name`；悬停仍能看到记录名。
- 不改变合并规则（同主题且相关 ≥60% 自动；只满足一项进待确认；都不达标不处理）。

## 2. 实现

- `src/relatedness.ts`：新增 `SYNONYM_GROUPS`（kaoyan/review/reminder/merge/release/config/docs/test/roadmap/goal/plan/policy/quality/bug 等 14 组），`tokenize` 在命中任一同义词时追加 `~<group>` 词元；ASCII 词含 `-`/`_` 时按分隔符再切，长度 ≥3 的子词也加入词元集。
- `src/client/ManagementPage.tsx`：自动合并列表与待确认列表均改为 `title={member.name}`、正文 `member.title ?? member.name`。
- 测试：`tests/relatedness.spec.ts` 新增同义词/子词用例；`tests/management-page.spec.tsx` 新增合并列表中文标题用例（mock 中带 `title`），并覆盖“没有标题时回退记录名”的既有行为。

## 4. 未测边界

- 同义词组是人工挑选的高置信集合，覆盖面有限；未收录的行业词仍只能靠原词/子词重叠。词面增强也可能把语义不相近的记录连到一起（例如共享 `merge` 但主题不同），仍需按“待确认”人工判断。
- 真实自动合并要等 DSH 重启后首次对账（约 20 秒）才发生；本轮只在单元/隔离环境验证了打分与分组。
- 62 分跨主题组重启后会重新出现在“待确认”（按新规则只要满足一项即询问），尚未在真实数据上点过“合并这一组”。
